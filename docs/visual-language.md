# あなた色写真展 - 演出のビジュアル言語

本書は、仕様書 `docs/README.md` が定めていない展示ディスプレイとiPadの演出の見た目を定める。演出の実装は本書に従い、仕様書と食い違う場合は仕様書を優先する。

## 1. 原則

- 展示ディスプレイの主役は、破片の群れと、選ばれた「色」である。展示ディスプレイには写真を置かない。写真は写真用の端末と結果ページだけで見せる。
- 画面を構成する要素は、色面、グラデーション（色のにじみ）、三角形の破片（3.2〜3.4節、4.4節）、ゆっくりした動きだけとする。iPadではこれに円と帯を加える。具体的な物、人、風景、文字記号を描かない（仕様書が定める色名、展示タイトル、操作文字を除く）。
- 一つの画面で同時に見える色面は、背景を除いて3面以下とする。
- 展示ディスプレイの色は、判定中から結果開始までの破片（3.3節、3.4節）を除き、輪郭のある形ではなく、背景へなだらかに溶けるグラデーションで表す。形は直線、帯、画面の縁からの距離だけで作り、円や点からの距離を使わない。縁はノイズでゆっくり揺らし、図形の輪郭に見せない。iPadの形の縁は塗りの境界だけで表す。影、半透明パネルは使わない。
- 動きは来場者が視界の端で変化に気づく程度の速さにする。一つの動きの所要時間は1.4秒以上とし、繰り返す動きの周期は12秒以上とする（指の操作へ直接応答する変形、iPadの質問の入れ替え、破片の光の筋が幅の端を抜けて消えたり現れたりする変化は除く。4.1節、4.3節、4.4節、4.5節）。
- 明るさが短い間隔で上下する演出（強い高速点滅）を使わない。明度の大きな切り替えは一回の体験の中で「判定の暗転」と「結果色の出現」の二回に限る。

### 1.1 使わない表現

写真作品と競合し、スクリーンセーバーや汎用の背景に見えるため、次を使わない。

- 発光するパーティクルの群れ
- ネオンのグロー（破片の下に敷く弱く広い光のにじみ「ブルーム」は、破片の輪郭より明るくならない範囲で使う。4.4節）
- すりガラス風のぼかしパネル
- 色の配置に意味がなく、色がばらばらに混ざり合いながら画面全体を流れ続けるメッシュグラデーション
- ランダムに漂う小さな点
- 紫から青への定番グラデーション
- 色相順に並んだパレットの帯（虹に見えるため）
- 中心から時計回りに一周する扇形のワイプ（スライドショーの定番トランジションに見えるため。最初の実装で violet に使い、作り直した）

実装を見て別の定番表現に寄っていた場合は、この一覧へ追加して作り直す。

## 2. 共通の決め方

### 2.1 時刻と決定性

展示ディスプレイの描画は、毎フレーム次の値だけから計算する。

- 補正済みサーバー時刻 `t`（`performance.timeOrigin + performance.now() + 時刻補正値`）
- 受信状態の `sessionId`、`phase`、`sequenceId`、`phaseStartedAt`、`phaseEndsAt`、`result`（色名、二色、写真ID）、`previewColorId`
- 自画面の `displayOrder`（URL `/display/N` の N − 1）
- `prefers-reduced-motion` の値

同じ入力からは同じ画面を描く。再接続した画面はほかの画面と同じ位置から再開する。実行のたびに変わる乱数は使わない（破片の配置は固定の種から作る。4.4節）。

### 2.2 画面ごとの違い

画面ごとの違いは `displayOrder` だけから作る。結果で見せる色（3.4節）が画面ごとに変わる。結果の二色が決まる前の破片は、全画面で同じ時刻に同じ位置、同じ色で描く。

### 2.3 イージング

- 出現と移動: `easeInOutSine`
- 結果色の広がり: `easeInOutSine`（縁のぼけ幅の分だけ遠くまで広げるため、序盤で一気に進む `easeOutCubic` では早く満ちて見える）
- 消える動き: `easeInSine`

### 2.4 基本色

| 用途                     | 色                       |
| ------------------------ | ------------------------ |
| 待機と質問の背景         | `#0B0B0B`（仕様書7.2.2） |
| 判定の暗転               | `#000000`                |
| 展示タイトル、iPadの文字 | `#E8E6E3`                |
| 補助文、無効表示         | `#8A8784`                |
| 線、無効な要素           | `#3A3836`                |

## 3. 展示ディスプレイ

### 3.1 `idle`、`intro`: 小さな輪と、色づいて広がる輪

写真は置かない。

`idle`: 仕様書7.2.3のとおり、背景 `#0B0B0B` に、`question`（3.2節）と同じ配置と動きの灰色の破片の輪を、不透明度100%のまま、輪の半径だけを0.3倍へ縮めて描く。破片の大きさは変えず、枚数は質問中の0.3倍（130枚のうち39枚）に減らす。結果や時間切れから `idle` へ戻るときは、質問中の大きさから3.0秒（`easeInOutSine`）で縮む。

`intro` の直前に再生するシーケンス（3.1.1節。仮データの `opening`）と `intro`: 待機の小さな灰色の輪が、シーケンスの開始から3.0秒（`easeInOutSine`）で、次のとおり散らばる。散らばり終えた破片は、`intro` の間そのまま動き続ける。

- 色: 破片を並び順でパレットの全色の基準色へ順に振り分け、灰色から色づける（3.3節と同じ色づけ）。
- 散らばり: 輪の内側の縁（画面短辺の38%）は動かさず、輪の内側は空けたまま、破片を外側へ押し出して画面いっぱいに散らばる。輪の中の位置が外側の破片ほど遠くへ動き、最も外側の破片は輪の半径の2.6倍（16:9の画面の隅に近い距離）まで届く。一部の破片は画面の外へはみ出す。
- 大きさ: 破片の大きさは質問中の2倍になる。
- 枚数: 質問中と同じ全枚数（130枚）になる。

`intro` の途中から接続した画面は、`intro` の経過時間にシーケンスの定義上の長さを足して、ほかの画面と同じ位置から続ける。reduced-motionでは、シーケンスの開始から広がり終えた状態で表示する。

文字: `intro` とその直前のシーケンスの間だけ、画面の中央に「あなた色写真展へようこそ」を `#E8E6E3` で表示する。文字の大きさは画面短辺の5%、字間は0.12emとし、シーケンスのコンポーネントの上に重ねる。直前のシーケンスの開始（シーケンスがなければ `intro` の `phaseStartedAt`）から3.0秒（`easeInOutSine`）でゆっくり現れ、シーケンスから `intro` へ移っても途切れない。`question` へ移ると1.5秒で消える。reduced-motionでは即時に現れ、即時に消える。

破片の位置は補正済みサーバー時刻だけから決まるので、`idle`、`intro`、`question` のあいだで切り替わっても輪は途切れずに動き続ける。

### 3.1.1 `sequence`: 連動演出

`sequence` の見た目は、シーケンスごとのSvelteコンポーネントで書く（`src/client/sequences/<id>/Controller.svelte` と `Display.svelte`）。展示ディスプレイでは待機の破片（3.1節）を描き続け、その上の全面にコンポーネントを重ねる。コンポーネントは破片を透かしても覆ってもよい。

コンポーネントにはpropsとして再生位置 `t`（補正済みサーバー時刻と `phaseStartedAt` の差。0から `durationMs` まで）、`durationMs`、`sessionId`、`reducedMotion` を渡し、展示ディスプレイ用には `displayOrder` も渡す。全画面の描画を同期させ、再接続しても同じ位置から続けられるよう、見た目はこれらの値だけから決める。乱数が要るときは `sessionId` から作り、`Math.random()` や端末の時計を直接使わない。reduced-motionの扱いもコンポーネントで決める。

再生が終わると次の段階へ切り替わる。`intro` と `question` も同じ破片を描くため、終わりの見た目は待機の破片に戻しておく。各シーケンスのコンポーネントがあることは、production buildの検証で確かめる。

### 3.2 `question`: 灰色の破片

構図: 三角形の破片の輪（4.4節の配置と動き）を灰色で描く。破片の明るさ（4.4節）をそのまま灰色の明るさにし、重なりで濃淡を作る。面の上には光源を映した細い光の筋を重ねる（4.4節）。破片は半透明なので、重なった部分では下の破片のアウトラインが上の破片越しに透けて見える。画面に出る明るさは、4.4節のハードライト合成をした後の値になる。色はまだ付けない。背景は `#0B0B0B`。

破片の位置は補正済みサーバー時刻から求めるので、全画面で同じ時刻に同じ位置になり、再接続した画面も同じ位置から再開する。

動き:

| 契機                                  | 動き                                       | 所要時間                                            |
| ------------------------------------- | ------------------------------------------ | --------------------------------------------------- |
| `question` に入る（`phaseStartedAt`） | `intro` の色づいて散らばった破片が、灰色の質問中の輪へ戻る（`intro` 以外から入るときは変わらない） |
| `idle` へ戻る（`phaseStartedAt`）     | 質問中の大きさの輪が、待機の小さな輪と枚数へ縮む | 3.0秒（`easeInOutSine`）                            |
| 常時                                  | 輪が時計回りに回りながら呼吸し、破片が揺れて自転する | 4.4節のとおり（輪の一周は基準150秒）                |

意図: 色は結果が決まるまで見せない。灰色の破片は、まだ色が決まっていないことを表す。どの色も見せないので、回答がどの色へ近づいているかは読み取れない。展示ディスプレイは回答に反応しない。一問確定しても、「戻る」を押しても、破片は常時の動き（輪の回転と呼吸、破片の揺れと自転）のまま変わらない。

### 3.3 `judging`: 暗転と色づき

`judging` の `phaseStartedAt` から、背景が `#0B0B0B` から `#000000` へ沈む（1.2秒、`easeInSine`）。灰色の破片は消さず、同じ1.2秒で破片全体の不透明度を元の40%まで下げ、そのまま動き続けてAIの選定を待つ。

AIが結果の二色を決めると、破片を二色で色づける。破片を並び順で一枚おきに一色目と二色目へ振り分け、灰色からそれぞれの基準色へ移す。同時に破片全体の不透明度を元の100%へ戻す（0.8秒、`easeInOutSine`）。明るい破片ほど色を白へ寄せ（最大35%）、重なりで濃淡を作る。どの画面も同じ二色で同じ破片を色づける。

色づき始める時刻は `judging` の `phaseEndsAt` の0.8秒前とし、結果開始の時刻に色づき終える。結果の配信時刻は全画面で共有できないが、サーバーは結果を配信してから0.8秒以上あとを結果開始にする（`SETTLE_MARGIN_MS`）ので、この時刻には全画面に結果が届いている。ただし `judging` の期限の0.8秒前より後に結果が決まると、結果開始は期限のままで、配信からの間隔が0.8秒より短くなる。このときは結果が届いた時点の進み具合から色づく。色づき始めるのは、早くても暗転の1.2秒を終えた後とする。結果開始は `judging` の開始から2秒より前にならない（`JUDGING_MS`）ので、通常はこの制限にかからない。色づきの0.8秒は1章の「一つの動きの所要時間は1.4秒以上」より短いが、結果の配信から結果開始までの最短の間隔に合わせるため、この長さにする。

AIの選定に失敗して最終問へ戻るときは、破片は灰色へ戻り、そのまま動き続ける（3.2節）。

意図: 全画面が一度静かに暗くなり、色を待つ時間を作る。色は結果が決まった時に初めて破片へ現れ、二色が混ざり合ったまま結果色の広がりへつながる。

### 3.4 `result`: 二色の出現

結果演出は `judging` の `phaseEndsAt`（= `result` の `phaseStartedAt`）に始まる。各画面は、AIが選んだ二色のうち自画面の色（`displayOrder` が偶数なら一色目、奇数なら二色目。仕様書7.2.4節）を見せる。最初の描画フレームで、すでにその色が起点から画面短辺の8%の位置まで見えている。全画面がこの時刻を補正済みサーバー時刻で待って切り替える（仕様書7.2.4節）。

演出は三段に分ける。

1. 広がり: 自画面の色の基準色（パレットの色そのもの）が、縁をぼかしたまま黒い画面を覆うまでにじみ広がる（下表の所要時間 `D`）。広がりは直線、帯、画面の縁のいずれかから測った距離で決め、円にならない。縁のぼけ幅は画面短辺の20%から75%へ広がり、縁はノイズでぼけ幅の±60%だけ揺れる。広がりの終わりには、揺れを含めても画面全体が基準色で塗りつぶされている。
2. 沈み: 全面が基準色から `backgroundColor` へ移る（`D` から1.0秒）。
3. 色名: タイポグラフィ表示の色名が現れる（`D + 0.4秒` から1.2秒）。

色づいた破片（3.3節）は、結果色が広がる間も、完了後も消えない。結果の二色で色づいたまま、広がる結果色の上に重なって動き続ける。

完了後は仕様書7.2.4のとおり、`backgroundColor` の全面に、色づいた破片と色名が残る。

広がり方は次の8種類とし、パレットの13色へ、色相の近い色が同じ広がり方にならないよう割り当てる（`RESULT_FORMS`、仮の割り当て）。

| 広がり方       | 形                                                                                           | `D`   | 割り当てる色   |
| -------------- | -------------------------------------------------------------------------------------------- | ----- | -------------- |
| `openingBand`  | 画面の高さの中央を通る水平線から、上下へ色が開く                                             | 1.6秒 | vermilion      |
| `risingSlant`  | 右下の隅から、左へ傾いた前線が昇るように色が満ちる                                           | 1.8秒 | orange         |
| `meetingTides` | 左右の端から色が流れ込み、中央で溶け合う                                                     | 1.4秒 | amber          |
| `fallingTide`  | 上端から色が降りてくる                                                                       | 1.6秒 | gold、sky      |
| `risingTide`   | 下端から水位が上がるように色がせり上がる                                                     | 2.2秒 | leaf、indigo   |
| `closingFrame` | 画面の四辺から内側へ色が満ちていく（四辺からの距離をなめらかに合わせ、隅の折れ目を出さない） | 2.0秒 | forest、blue   |
| `sweepingTide` | 色が横へ流れ込む。偶数の `displayOrder` は左から、奇数は右から                               | 1.6秒 | emerald、rose  |
| `diagonalTide` | 左上の隅から右下の隅へ、斜めの前線で色がゆっくり伸びる                                       | 2.6秒 | jade、wisteria |

全画面が同じ時刻に始まる。二色の広がり方は異なりうるため、隣り合う画面で形と所要時間が変わることがある（`sweepingTide` は向きも画面ごとに変わる）。縁を揺らすノイズは結果開始時刻からの経過秒で流す。

結果開始後に接続または再接続した画面は、演出を再生せず完了状態を即時に表示する（仕様書7.2.4）。

### 3.5 管理画面からの表示確認（`previewColorId`）

`idle` で `previewColorId` が設定されている間は、全画面にその色の結果完了状態（`backgroundColor`、その色で色づけた破片、タイポグラフィの色名）を演出なしで表示する。

### 3.6 `idle` へ戻るとき

`result` または強制リセットから `idle` へ戻ると、それまでの背景色が1.0秒で消え、待機の灰色の破片だけが残る。

## 4. iPad

### 4.1 共通

- 背景 `#FFFFFF`、文字 `#000000`。主操作のボタンは `#000000` の塗りに `#FFFFFF` の文字、角丸なしの帯形とする。
- 待機画面の「はじめる」のボタンは、押している間だけ0.96倍に縮み、矢印が右へ6px動く。縮小と移動は120msで行い、離すと同じ時間で戻す。`prefers-reduced-motion: reduce` が有効なときは時間をかけずに切り替える。
- 文字は抽象グラフィックスの上へ重ねない。

### 4.2 状態ごとの構図

| 状態       | 構図                                                                                                                     | 動き                                        |
| ---------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------- |
| `idle`     | 中央に歓迎文言（`welcomeMessage`）と「はじめる」のボタン。ボタンは文字の右に矢印を置く                                   | 押している間、縮小と矢印の移動（4.1節）     |
| 受付停止   | 中央に展示タイトルと受付停止の案内文言を表示し、開始ボタンを置かない                                                     | なし                                        |
| `sequence` | 中央にシーケンスの `Controller.svelte` を表示する（3.1.1節）                                                             | コンポーネントで決める                      |
| `intro`    | 進捗バー、見出し、ニックネームの入力欄と「→」ボタンを表示する                                                            | なし                                        |
| `question` | 上部に進捗バー。中央に質問文と入力（4.3節）、下部に「戻る」「次へ」                                                      | 確定待ちのつまみとピンの点線が回る（4.3節）。質問の入れ替え（4.5節） |
| `judging`  | 中央に「あなたの色を選んでいます」だけを置く                                                                             | なし                                        |
| `result`   | 一色目の `backgroundColor` の全面。二色の混色の円（色面）、色名、二色の名前、読み取り、QRコード、結果URL、「最初に戻る」 | 色面の円が20%の大きさから広がる（1.4秒）    |

`result` の色面は、二色を直線補間した13段のグラデーション（仕様書6.2節）で塗った円とする。縦向きは円、色名、二色の名前、読み取り、QRコード、URL、ボタンを縦に並べる。横向きは左に円と文字、右にQRコードとボタンを置く。QRコードは仕様書10.3節のとおり白地に黒で描き、結果の色で着色しない。

### 4.3 入力の状態

仕様書7.1節の5状態を、スライダーと2Dマップではつまみやピンの形、枠、ラベルで見分ける。色だけで区別しない。つまみとピンはスナップせず指に付いて動くため、位置の移動は補間せず、大きさだけを120msで変化させる。

スライダーは、画面全体を縦の仕切り線で左右に分ける。仕切り線の左の領域に左の語（`leftLabel`）、右の領域に右の語（`rightLabel`）を置き、広い側の語を選んでいるとみなす。回答が左の語に近いほど仕切り線は右へ寄り、左の語が大きく、右の語が小さくなる（文字の大きさは左右が同じ広さのとき24px、端では広い側が約53px、狭い側が13px）。狭い側の語も読める幅を残すため、仕切り線は画面幅の15%から85%の範囲で動く。仕切り線の上下中央には、左右の矢印が付いたつまみを置く。進捗バーと質問文を含め、画面のほぼ全域で触れた指の位置へ仕切り線が動く。そのため、語の上をタップすると、その語の側は狭くなり、回答は反対側の語へ寄る。押し間違いで回答が変わらないよう、下部のボタン列は触れても仕切り線を動かさない。仕切り線は質問文と重なる上部を薄くする。質問文の下には、状態に応じたラベルを置く。

| 状態                   | つまみ                  | 枠           | 質問文の下のラベル                                             |
| ---------------------- | ----------------------- | ------------ | -------------------------------------------------------------- |
| 未回答                 | 画面中央の直径40pxの円  | 破線         | 「しっくりくる位置に動かしてください。真ん中でも大丈夫です。」 |
| 操作中                 | 直径48pxの円            | 太い実線     | 最も近い回答位置の補助文                                       |
| 確定待ち               | 直径40pxの円            | 点線が回る輪 | 「送信しています」                                             |
| 確定済み（戻ったとき） | 直径40pxの円            | 二重線       | 「回答済み: {補助文}」                                         |
| 無効                   | 直径40pxの円、`#3A3836` | 枠なし       | 「操作できません」                                             |

| ---------------------- | ------------------------------ | ------------ | -------------------------------- |

### 4.4 破片の配置

半透明の細長い三角形（破片）で作る輪の配置と動きを、展示ディスプレイの質問中から結果色が広がり始めるまで（3.2〜3.4節）の仕様として次のとおり決める（`src/shared/shards.ts`）。輪は、結果の二色が決まるまでは灰色で、決まった後は二色で描く（3.3節）。

- 輪: 画面中央を中心とし、半径は画面短辺の38%（下の「呼吸」で基準の0.9〜1.1倍に変わる）。破片130枚を半径の±20%の範囲へ中心線付近ほど密に散らし、輪の内側を空ける。破片は輪の接線方向を向く。輪の外側の一部は画面短辺方向の端（横長の画面では上下の端）を越えることがあり、呼吸で輪が大きいほど越える頻度と量が増える。はみ出す量は最大で画面短辺の約9%（1920×1080の画面で約100 CSS画素）。
- 破片: 長さは輪の半径の14〜34%。明るさ150〜255、不透明度30〜75%。輪郭に、塗りの色を白へ12%寄せた太さ1 CSS画素のアウトラインを、塗りと同じ不透明度で描く。線は輪郭を中心にして引き、先に描いて塗りを重ねるので、内側の半分は塗りの下になり、破片は輪郭の外側へ0.5 CSS画素広がる。角は丸め、細い三角形の鋭い角でアウトラインが頂点の先へ伸びないようにする。ハードライト合成は暗い背景の上で明るさの差を広げるため（下の「合成」）、白へ寄せる割合を小さく取る。明るさ150、不透明度75%の破片では、塗りが約43/255、アウトラインの外側の半分が約61/255になる。
- 動き: 輪は時計回りに基準150秒（速さは破片ごとに±20%）で一周し、半径方向に14〜32秒周期でわずかに揺れる。破片は約130〜330秒周期でゆっくり自転する。
- 呼吸: 輪全体の半径を基準の0.9〜1.1倍の範囲でゆっくり不規則に増減させ、輪をふくらませたり縮めたりする。周期15秒、23秒、41秒の三つの正弦波を重み0.5、0.3、0.2で重ね、周期の比を互いに素な15:23:41にして、ふくらむ深さと間隔を毎回変える。三つを重ねた呼吸は14,145秒（約3.9時間）で同じ形へ戻る。半径の変化は100ミリ秒あたり0.4%未満になる。一つの呼吸（ふくらみの頂点から次の頂点まで）は12.46〜17.09秒であり、この長さによって1章の「繰り返す動きの周期は12秒以上」という決まりを満たす。各波の周期をあと4%ほど短くすると一つの呼吸が12秒を切るので、この組み合わせを1章の決まりを満たす限界に近い速さの設定とする。ふくらみと縮みの向きは5〜9秒ごとに入れ替わる。補正済みサーバー時刻から求めるので、全画面で同じ時刻に同じ大きさになる。回答には反応しない（3.2節）。
- 初期配置は固定の種から作る擬似乱数で決め、位置は3.2節のとおり時刻から求める。
- 合成: 破片はハードライト合成で下の色面とブルームへ重ねる。ハードライトはRGBの成分ごとに、値を0〜1として、破片の成分が半分より明るければ `下 + (2×破片 − 1)×(1 − 下)`、それ以外は `2×破片×下` になる。灰色の破片は明るさが150〜255で半分より明るいので下の色を明るくするが、その強さは `2×破片 − 1` で、明るさ150の破片では0.18にとどまる。このため質問中の背景 `#0B0B0B` の上では、最も明るい破片以外は通常の重ね方より暗く見え（明るさ150、不透明度75%の破片は約43/255。通常の重ね方では約115/255）、破片どうしの明暗の差が大きくなる。ブルームが下にある場所では、破片はその分明るく見える。結果の二色で色づけた後は、半分より暗い成分で下の色の同じ成分を暗くする。破片を描かない間はハードライト合成をやめ、通常の重ね方に戻す。
- 光の筋: 破片を、長い向きを軸にわずかに曲げた鏡と見なし、画面の左上の手前に置いた点光源の映り込みを、面の上を走る細い光の筋として白で重ねる。
  - 光源と鏡: 光源は画面幅の20%、画面の高さの15%の位置に置き、画面から手前へ画面短辺の50%離す。視点は画面の正面の無限遠に置く。破片の長い向きは頂点の主成分の向きとし、正三角形に近い破片でも筋が形の長い向きに沿うようにする。曲げた鏡では、面の法線が光源の向きと視点の向きの中間の向きに最も近づく場所が、長い向きに沿う一本の線になる。面の法線は幅の中央から端までで0.6ラジアン倒れる。幅の中央の法線には破片ごとに±0.1ラジアンの偏りを持たせ、さらに14〜24秒周期、振れ幅0.6ラジアンで幅の向きにゆっくり揺らす。この揺れと自転によって法線が中間の向きに最も近づく位置が幅の向きに動き、筋が面の上を走る。光源からの距離による減衰は入れず、筋の幅は破片の幅によらず一定にする。
  - 明るさと描画: 筋の明るさはBlinn-Phongの式（指数120）で求め、画面へ射影した破片の長い向きが、光源と視点の中間の向きを画面へ射影した向きと直交するときに最も明るく、そろうほど暗くなる。筋の明るさが0.05未満のときと、中心線が破片の幅の外へ3 CSS画素より遠く出たときは描かない。筋は全長6 CSS画素の線形グラデーションで、両端を透明にし、中央を最も明るくする。明るさが中心線の半分以上になる芯の幅は約1.5 CSS画素。中心線の不透明度は、筋の明るさ、破片ごとの不透明度（30〜75%）、破片全体の不透明度（判定中の減光や消え方を含む）を掛けた値になる。背景 `#0B0B0B` の上（破片全体の不透明度100%）では、明るさ150、不透明度75%の破片の中心線はハードライト合成の後で、筋なしの約43/255から、筋の明るさ0.5で約123/255、1で約202/255になる（中心線そのものの値。1 CSS画素が1画素の画面では、画素内の平均により筋の明るさ1のとき約178/255になる）。結果の二色で色づけた後も白のまま描く。
  - 変化の速さ: 1920×1080の画面における呼吸の一周期（約3.9時間）では、筋のある破片は130枚のうち16〜55枚で、筋の明るさが0.5を超える破片は多くて33枚になる。100ミリ秒あたり、筋の明るさの変化は0.035未満（実測で約0.032）、移動量は5 CSS画素未満（実測で約4.2 CSS画素）にとどまり、点滅にはならない（1章）。移動量は画面の大きさに比例し、3840×2160の画面では約2倍になる。筋が破片の幅の端を抜けるときは、三角形の頂点に向かって筋が短くなりながら消える（端から入るときは頂点の側から伸びて現れる）。端を抜けるときは長さが0になるまで縮んで消え、明るさが下限（0.05）を切って消えるときはすでに中心線の不透明度が0.04未満まで下がっているため、どちらの場合も筋が途中で急に途切れることはない。消えたり現れたりするまでの時間は筋の走る速さや測り方によって変わり、0.1秒ほどから数秒まで幅があるため、特定の値には定めない。1.4秒に満たないことがあるので、この変化は1章の「一つの動きの所要時間は1.4秒以上」という決まりの例外とする。
- ブルーム: 破片の周りに、弱く広い光のにじみを重ねる。破片の描画をぼかしたものを、不透明度45%のスクリーン合成で画面の色面へ重ねる。ぼかしは二段で、標準偏差は画面短辺の1.2%（重み35%）と4.5%（重み65%）。破片の色、不透明度、消え方にそのまま従う。アウトラインと光の筋はブルームの解像度（7章）では1画素に満たず、ぼかすと見えないので描かない。

### 4.5 質問の入れ替え

「次へ」または「戻る」で質問が切り替わると、前の質問が横へずれながら消え、次の質問が反対側から現れる（`src/client/controller/question-transition.ts`）。進むときは前の質問が左へずれながら消え、次の質問が右から現れる。戻るときは向きを逆にする。進捗バーと下部のボタン列は動かさない。

| 動き             | 内容                                                       | 所要時間 | イージング     |
| ---------------- | ---------------------------------------------------------- | -------- | -------------- |
| 前の質問が消える | 32px横へずれながら、不透明度を1から0へ下げる               | 240ms    | `easeInSine`   |
| 次の質問が現れる | 前の質問が消えてから、32px離れた位置から本来の位置へ移りつつ、不透明度を0から1へ上げる | 480ms    | `easeOutCubic` |

- 前後の質問は同じ区画に重ね、二つの質問が縦に並んで質問や下部のボタン列の位置が上下にずれないようにする。消える質問は操作を受け付けず、読み上げにも出さない（`inert`）。現れる質問は、動き始めるまで表示せず（`visibility: hidden`）、見えない入力に触れて回答が変わらないようにする。
- 入れ替えの間は「戻る」「次へ」と入力を無効にする。入れ替えの途中で次の切り替えが起きると、現れかけの質問が一瞬はっきり見えるためと、ずれて半透明の入力に触れて回答が変わらないようにするため。仕様書7.1節の「新しい状態が届くまで無効」の期間に、この720msを加える。
- スライダーの質問では、操作面が画面全体に広がっているため、質問全体の位置はずらさずに不透明度だけを変え、その中で質問文と案内文（`guide`）だけを横へずらす。
- 1章の「一つの動きの所要時間は1.4秒以上」という原則は、来場者が視界の端で変化に気づく速さを決めたもので、iPadを操作している来場者には遅すぎる。質問の入れ替えは「次へ」「戻る」を押した操作への応答とみなし、合計720msで終える。
- 明るさは変えない（背景は白のまま）。
- `intro` から最初の質問へ移るとき、最後の質問から `judging` へ移るときは入れ替えをせず、即時に切り替える。

## 6. `prefers-reduced-motion: reduce`

動きを止めても状態が伝わるように、各状態を色面の切り替えと静止した構図で表す。

| 状態                             | 通常                               | reduced-motion                                                                          |
| -------------------------------- | ---------------------------------- | --------------------------------------------------------------------------------------- |
| 展示 `idle`                      | 1秒のクロスフェード                | 8秒ごとに即時切り替え（仕様書7.2.3）                                                    |
| 展示 `sequence`                  | コンポーネントで決める（3.1.1節）  | コンポーネントで決める。仮データの `opening` は何も重ねず、破片の色づきと広がりは本体が描く（3.1節）   |
| 展示 `question` 開始             | 小さな輪が質問中の大きさへ広がる   | 質問中の大きさの輪を即時に表示（`idle` へ戻るときも小さな輪へ即時に切り替える）        |

| 展示 `result`                    | 色が広がり、沈み、色名が現れる     | 基準色の全面を1.6秒表示し、`backgroundColor` と色名の完了状態へ切り替える               |
| 展示 `idle` へ戻る               | 1秒で消える                        | 即時切り替え                                                                            |
| iPad `sequence`                  | コンポーネントで決める（3.1.1節）  | コンポーネントで決める。仮データの `opening` は文言をフェードせず即時に切り替える       |

reduced-motionでの基準色→完了状態の切り替えは一回だけで、繰り返さない。

## 7. 描画方式

- 展示ディスプレイの塗りとグラデーションは全面の `<canvas>` 一枚に描く。このcanvasはなだらかなグラデーションと全面の塗りしか描かないので、CSS画素の半分の解像度で描いて引き伸ばし、フラグメントシェーダーの負荷を `devicePixelRatio` に依存させない。色名のタイポグラフィはcanvasの上のDOM要素とする。
- 質問中から結果色が広がり始めるまでの破片は、その上に重ねたもう一枚の `<canvas>` へcanvas 2Dで描く。破片の輪郭を見せるため、こちらはCSS画素の2倍までの解像度で描き、`mix-blend-mode: hard-light` で下の色面とブルームへ重ねる。合成先を展示ディスプレイの要素の中に限るため、その要素に `isolation: isolate` を指定する。
- 破片のブルームは、色面のcanvasと破片のcanvasの間に置いた三枚目のcanvasへ、CSS画素の1/8の解像度で描く。破片をこの解像度で描き直し、canvas 2Dの `filter` でぼかして写し、`mix-blend-mode: screen` で下の色面へ重ねる。`filter` を使えない環境ではブルームを描かない。
- 塗りとグラデーションのcanvasはWebGL2のフラグメントシェーダーで描く（`src/client/display/renderer.ts`）。一フレームの描画内容（塗り、結果色のにじみ）を一度に合成し、グラデーションの部分だけに1階調未満のディザをかけて暗い色の段差を消す。全面の塗りの部分は指定色をそのまま出力する。
- WebGL2を使えない環境では、canvas 2Dの線形グラデーションで結果色のにじみを近似する（ノイズの揺れは描かない）。
- WebGL2のcanvasは描画結果を次の描画まで保持し（`preserveDrawingBuffer`）、テストは三枚のcanvasを作業用のcanvas（canvas 2D）へ順に重ねて写し、画素を読む。ブルームと破片のcanvasは画面と同じ不透明度と合成方法で重ねる。ただし破片のcanvasを色面のcanvasの解像度へ縮めて合成するため、破片の輪郭では画面と値が少し変わる。
- 毎フレームの描画内容は純粋関数で計算し、描画処理と分ける。純粋関数は同じ入力に同じ結果を返すことを単体テストで確認する。
- 色面のcanvasは、動きのない状態（`result` 完了後）では描き直さない。破片のcanvasは常に動くので毎フレーム描く。
