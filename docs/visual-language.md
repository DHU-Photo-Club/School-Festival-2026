# あなた色写真展 - 演出のビジュアル言語

本書は、仕様書 `docs/README.md` が定めていない展示ディスプレイとiPadの演出の見た目を定める。演出の実装は本書に従い、仕様書と食い違う場合は仕様書を優先する。

## 1. 原則

- 主役は写真作品と、選ばれた「色」である。グラフィックスは写真を見る前後の時間だけに現れ、写真の表示中は背景色以外を描かない。
- 画面を構成する要素は、色面、円、帯、弧、グラデーション、ゆっくりした動きだけとする。具体的な物、人、風景、文字記号を描かない（仕様書が定める色名、展示タイトル、操作文字を除く）。
- 一つの画面で同時に見える色面は、背景を除いて3面以下とする。
- 形の縁は塗りの境界だけで表し、光彩、ぼかし、影、半透明パネルを使わない。
- 動きは来場者が視界の端で変化に気づく程度の速さにする。一つの動きの所要時間は1.4秒以上とし、繰り返す動きの周期は12秒以上とする。
- 明るさが短い間隔で上下する演出（強い高速点滅）を使わない。明度の大きな切り替えは一回の体験の中で「判定の暗転」と「結果色の出現」の二回に限る。

### 1.1 使わない表現

写真作品と競合し、スクリーンセーバーや汎用の背景に見えるため、次を使わない。

- 発光するパーティクルの群れ
- ネオンのグロー
- すりガラス風のぼかしパネル
- 画面全体を流れ続けるメッシュグラデーション
- ランダムに漂う小さな点
- 紫から青への定番グラデーション
- 色相順に並んだ8色の帯（虹に見えるため。8色を並べるときは2.2節の並べ替えを使う）
- 中心から時計回りに一周する扇形のワイプ（スライドショーの定番トランジションに見えるため。最初の実装で violet に使い、作り直した）

実装を見て別の定番表現に寄っていた場合は、この一覧へ追加して作り直す。

## 2. 共通の決め方

### 2.1 時刻と決定性

展示ディスプレイの描画は、毎フレーム次の値だけから計算する。

- 補正済みサーバー時刻 `t`（`performance.timeOrigin + performance.now() + 時刻補正値`）
- 受信状態の `sessionId`、`phase`、`phaseStartedAt`、`phaseEndsAt`、`revision`、`resultColorId`、`previewColorId`
- 自画面の `displayOrder` と `displayManifest` の登録件数
- `prefers-reduced-motion` の値

同じ入力からは同じ画面を描く。再接続した画面はほかの画面と同じ位置から再開する。乱数は使わず、`sessionId` から作るハッシュ値を種にする。

### 2.2 8色の並べ替え

8色を同時に並べる場面では、`sessionId` のハッシュ値から並び順を決める。並び順は同じセッションの間は全画面で同じで、セッションごとに変わる。`sessionId` が `null` の画面（iPadの待機）は、色相が隣り合わない固定順 `red, cyan, yellow, violet, green, magenta, blue, orange` を使う。

### 2.3 画面ごとの違い

画面ごとの違いは `displayOrder` だけから作る。質問中の輪は、`displayOrder` が1増えるごとに輪を一区画（45°）戻して見せる。輪は時計回りに回るので、一問確定するたびに、ある画面に見えていた色が右隣の画面へ移る。教室を歩くと、隣の画面に色が続いて見える。

### 2.4 イージング

- 出現と移動: `easeInOutSine`
- 結果色の広がり: `easeOutCubic`
- 消える動き: `easeInSine`

### 2.5 基本色

| 用途 | 色 |
| --- | --- |
| 待機と質問の背景 | `#0B0B0B`（仕様書7.2.2） |
| 判定の暗転 | `#000000` |
| 展示タイトル、iPadの文字 | `#E8E6E3` |
| 補助文、無効表示 | `#8A8784` |
| 線、無効な区画 | `#3A3836` |

## 3. 展示ディスプレイ

### 3.1 `idle` と `intro`: 写真の巡回

仕様書7.2.3のとおり、背景 `#0B0B0B` に写真を一作品ずつ表示し、8秒枠の先頭1秒でクロスフェードする。この状態ではグラフィックスを描かない。待機中の主役は写真である。

`displayOrder >= P` の画面は、画面中央に展示タイトル「あなた色写真展」を `#E8E6E3` で表示する。文字の大きさは画面短辺の6%とし、ほかの要素を置かない。

`intro` では `idle` の巡回をそのまま続ける。`intro` 中に新しく接続した画面は、直前の `idle` の開始時刻を知らないので、`intro` の `phaseStartedAt` を巡回の基準にする。

### 3.2 `question`: 巡る色の輪

構図: 各画面の下端より下に中心を置いた、一本の太い輪（円環）を描く。輪は8色の等しい区画（各45°）でできていて、画面には輪の上側だけがアーチとして見える。一画面に見える区画は2〜3面になる。

| 値 | 横長画面（幅 `w`、高さ `h`、短辺 `m`、長辺 `M`） |
| --- | --- |
| 中心 | `(0.5w, h + 0.56m)` |
| 外径 | `0.78M` |
| 帯の太さ | `0.48m` |

縦長画面は同じ式を使う（`m` と `M` が入れ替わるだけで、輪は画面下側に大きく現れる）。

区画の並び順は2.2節のとおり `sessionId` から決める。輪の回転角は次で求める。

```text
角度 = 基準角(sessionId) + (revision − displayOrder) × 45°（12時方向から時計回り）
```

動き:

| 契機 | 動き | 所要時間 |
| --- | --- | --- |
| `question` に入る（`phaseStartedAt`） | 写真が消え、帯の太さが0から広がって輪が現れる | 写真の消失1.5秒、輪の出現3.0秒（0.6秒遅れて開始） |
| `revision` が増える（一問確定） | 輪が一区画（45°）だけ回る。同時に帯が8%太くなり、元の太さへ戻る | 6.0秒 |
| 常時 | 輪の外径が±1.5%の幅で呼吸する | 周期12秒 |

`revision` が増えた時刻は、サーバーが最後にiPad操作を受理した時刻 `phaseEndsAt - 5分` を使う（仕様書8.2節で `question` の `phaseEndsAt` は最終操作から5分後）。全画面が同じ時刻から回り始め、途中で再接続した画面も同じ角度から再開する。

意図: 一問答えるたびに、すべての色が一つずつ隣へ移る。8色はいつも同じ面積で並び、どの色も強調しないので、回答がどの色へ近づいているかは読み取れない。展示ディスプレイには回答内容が届かないので、反応は「一問確定した」ことだけを伝える。「戻る」も `revision` を増やすため、同じ回転が起きる。

### 3.3 `judging`: 暗転

`judging` の `phaseStartedAt` から、輪の帯が細くなって消え（1.2秒、`easeInSine`）、背景が `#0B0B0B` から `#000000` へ沈む（1.2秒）。残りの0.8秒は黒のまま保つ。

意図: 全画面が一度静かに暗くなり、次に現れる色を待つ時間を作る。

### 3.4 `result`: 結果色の出現

結果演出は `judging` の `phaseEndsAt`（= `result` の `phaseStartedAt`）に始まる。最初の描画フレームで、すでに結果色の形が画面短辺の8%の大きさで見えている。このフレームが同期計測の基準になる（仕様書8.7節）。

演出は三段に分ける。

1. 広がり: 結果色の基準色の形が、黒い画面を覆うまで広がる（下表の所要時間 `D`）。
2. 沈み: 全面が基準色から `backgroundColor` へ移る（`D` から1.0秒）。
3. 写真: 割り当てられた写真、またはタイポグラフィ表示の色名が現れる（`D + 0.4秒` から1.2秒）。

完了後は仕様書7.2.4のとおり、`backgroundColor` の全面に写真か色名だけが残る。

8色の広がり方は、仕様書6.2節の「写真の方向性」から決める。

| 色 | 広がり方 | `D` | 写真の方向性との対応 |
| --- | --- | --- | --- |
| red | 画面中央から円が広がる | 1.6秒 | 熱、生命、近距離。中心から近く満ちる |
| orange | 下端中央を中心にした半円が昇りながら広がる | 1.8秒 | 夕方、親密さ、温度。低い位置からの暖かさ |
| yellow | 上端中央を中心にした半円が降りながら広がる | 1.6秒 | 光、開放感、軽さ。上から差す光 |
| green | 下端から水平な帯がせり上がる | 2.2秒 | 植物、水、静かな成長。ゆっくり伸びる |
| cyan | 縦の帯が横へ掃く。偶数の `displayOrder` は左から、奇数は右から | 1.6秒 | 透明感、風、反射。隣の画面と鏡写しになる |
| blue | 画面の縁から内側へ輪が閉じる | 2.0秒 | 夜、奥行き、集中。中心へ向かう |
| violet | 左上の隅を中心にした円が、対角へ向かってゆっくり伸びる | 2.6秒 | 影、余韻、非日常。影が伸びるように最も長く余韻を残す |
| magenta | 左右の端から二つの円が広がり、中央で出会う | 1.4秒 | 華やかさ、遊び、躍動。最も軽快 |

全画面が同じ時刻に同じ形で始まり、同じ時刻に終わる（cyanだけは向きが画面ごとに変わる）。

結果開始後に接続または再接続した画面は、演出を再生せず完了状態を即時に表示する（仕様書7.2.4）。

### 3.5 管理画面からの表示確認（`previewColorId`）

`idle` で `previewColorId` が設定されている間は、その色の結果完了状態（`backgroundColor` と割り当て写真、またはタイポグラフィ）を演出なしで表示する。

### 3.6 `idle` へ戻るとき

`result` または強制リセットから `idle` へ戻ると、それまでの画面が1.0秒で消え、待機の写真が現れる。

## 4. iPad

### 4.1 共通

- 背景 `#0B0B0B`、文字 `#E8E6E3`。主操作のボタンは `#E8E6E3` の塗りに `#0B0B0B` の文字、角丸の帯形とする。
- 画面の象徴として、展示ディスプレイと同じ8区画の輪（以下「輪」）を小さく置く。輪の区画の並び順と回転は2.2節、3.2節と同じ計算を使う（`displayOrder` の項は0）。
- 文字は抽象グラフィックスの上へ重ねない。

### 4.2 状態ごとの構図

| 状態 | 構図 | 動き |
| --- | --- | --- |
| `idle` | 画面上部に直径 `min(56vmin, 420px)` の輪。その下に展示タイトルと「診断をはじめる」 | 輪が240秒で一周する |
| 受付停止 | 輪の全区画を `#3A3836` にする。案内文を表示し、開始ボタンを置かない | なし |
| `intro` | 輪を直径 `min(28vmin, 200px)` に縮め、所要時間と診断の位置づけを表示する | 輪が240秒で一周する |
| `question` | 上部に直径64pxの輪と `3 / 7`。中央に質問文、下部にスライダーと「戻る」「次へ」 | `revision` が増えると輪が一区画回る（1.4秒） |
| `judging` | 中央に輪だけを置き、その下に「あなたの色を選んでいます」 | 輪の帯が細くなり、中心へ縮んで消える（1.6秒） |
| `result` | `backgroundColor` の全面。基準色の円（色面）、色名、メッセージ、QRコード、結果URL、「最初に戻る」 | 色面の円が20%の大きさから広がる（1.4秒） |

`result` の色面は基準色の円とする。縦向きは円、色名、メッセージ、QRコード、URL、ボタンを縦に並べる。横向きは左に円と文字、右にQRコードとボタンを置く。QRコードは仕様書10.3節のとおり白地に黒で描き、結果色で着色しない。

### 4.3 スライダーの状態

仕様書7.1節の5状態を、つまみの形、枠、ラベルで見分ける。色だけで区別しない。

| 状態 | つまみ | 枠 | トラック下のラベル |
| --- | --- | --- | --- |
| 未回答 | 中央に薄く表示した直径28pxの円 | 破線 | 「動かして選んでください」 |
| 操作中 | 直径40pxの円 | 太い実線 | 選択中の位置の補助文 |
| 確定待ち | 直径28pxの円 | 点線が回る輪 | 「送信しています」 |
| 確定済み（戻ったとき） | 直径32pxの円 | 二重線 | 「回答済み: {補助文}」 |
| 無効 | 直径28pxの円、`#3A3836` | 枠なし | 「操作できません」 |

| yellow | `#E5B83B` | `#45360F` | `#FBF1D6` | 輪の一区画 | 上から降りる半円 |
| green | `#2F9B78` | `#10392C` | `#DDF2EA` | 輪の一区画 | 下からせり上がる帯 |
| cyan | `#39A8B8` | `#0F363D` | `#DCF1F4` | 輪の一区画 | 横へ掃く帯 |

`backgroundColor` は基準色の色相を保った深い色とし、写真の周りを結果色に染めながら写真より明るくならないようにする。`foregroundColor` との比は全色で10:1以上（基準4.5:1）。結果では、明るい基準色が部屋を満たした後に深い `backgroundColor` へ沈み、写真が浮かび上がる。

## 6. `prefers-reduced-motion: reduce`

動きを止めても状態が伝わるように、各状態を色面の切り替えと静止した構図で表す。

| 状態 | 通常 | reduced-motion |
| --- | --- | --- |
| 展示 `idle` | 1秒のクロスフェード | 8秒ごとに即時切り替え（仕様書7.2.3） |
| 展示 `question` 開始 | 輪が広がって現れる | 輪を静止した状態で即時に表示 |
| 展示 `question` 一問確定 | 輪が6秒かけて一区画回る | 輪を一区画回した構図へ即時に切り替える。呼吸しない |
| 展示 `judging` | 1.2秒で暗転 | 即時に `#000000` |
| 展示 `result` | 色が広がり、沈み、写真が現れる | 基準色の全面を1.6秒表示し、`backgroundColor` と写真（または色名）の完了状態へ切り替える |
| 展示 `idle` へ戻る | 1秒で消える | 即時切り替え |
| iPad 全状態 | 輪の回転、縮小、色面の広がり | すべて静止。`judging` は細い輪と文言だけを表示する |

reduced-motionでの基準色→完了状態の切り替えは一回だけで、繰り返さない。

## 7. 描画方式

- 展示ディスプレイのグラフィックスは全画面の `<canvas>` 一枚に描き、`devicePixelRatio` に合わせて解像度を上げる。写真とタイポグラフィはcanvasの上のDOM要素とし、写真には仕様書7.2.2のとおりフィルターをかけない。
- 毎フレームの描画内容は純粋関数で計算し、描画処理と分ける。純粋関数は同じ入力に同じ結果を返すことを単体テストで確認する。
- 動きのない状態（写真表示中、`result` 完了後）はcanvasを描き直さない。
