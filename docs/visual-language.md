# あなた色写真展 - 演出のビジュアル言語

本書は、仕様書 `docs/README.md` が定めていない展示ディスプレイとiPadの演出の見た目を定める。演出の実装は本書に従い、仕様書と食い違う場合は仕様書を優先する。

## 1. 原則

- 主役は写真作品と、選ばれた「色」である。グラフィックスは写真を見る前後の時間だけに現れ、写真の表示中は背景色以外を描かない。
- 画面を構成する要素は、色面、グラデーション（色のにじみ）、三角形の破片（3.2節、4.4節）、ゆっくりした動きだけとする。iPadではこれに円と帯を加える。具体的な物、人、風景、文字記号を描かない（仕様書が定める色名、展示タイトル、操作文字を除く）。
- 一つの画面で同時に見える色面は、背景を除いて3面以下とする。
- 展示ディスプレイの色は、質問中の破片（3.2節）を除き、輪郭のある形ではなく、背景へなだらかに溶けるグラデーションで表す。形は直線、帯、画面の縁からの距離だけで作り、円や点からの距離を使わない。縁はノイズでゆっくり揺らし、図形の輪郭に見せない。iPadの形の縁は塗りの境界だけで表す。影、半透明パネルは使わない。
- 動きは来場者が視界の端で変化に気づく程度の速さにする。一つの動きの所要時間は1.4秒以上とし、繰り返す動きの周期は12秒以上とする（指の操作へ直接応答する変形は除く。4.1節、4.3節）。
- 明るさが短い間隔で上下する演出（強い高速点滅）を使わない。明度の大きな切り替えは一回の体験の中で「判定の暗転」と「結果色の出現」の二回に限る。

### 1.1 使わない表現

写真作品と競合し、スクリーンセーバーや汎用の背景に見えるため、次を使わない。

- 発光するパーティクルの群れ
- ネオンのグロー
- すりガラス風のぼかしパネル
- 色の配置に意味がなく、色がばらばらに混ざり合いながら画面全体を流れ続けるメッシュグラデーション（展示ディスプレイの色は、位置を2.2節と3.2節の並びで決める）
- ランダムに漂う小さな点
- 紫から青への定番グラデーション
- 色相順に並んだパレットの帯（虹に見えるため。パレットの色を並べるときは2.2節の並べ替えを使う）
- 中心から時計回りに一周する扇形のワイプ（スライドショーの定番トランジションに見えるため。最初の実装で violet に使い、作り直した）

実装を見て別の定番表現に寄っていた場合は、この一覧へ追加して作り直す。

## 2. 共通の決め方

### 2.1 時刻と決定性

展示ディスプレイの描画は、毎フレーム次の値だけから計算する。

- 補正済みサーバー時刻 `t`（`performance.timeOrigin + performance.now() + 時刻補正値`）
- 受信状態の `sessionId`、`phase`、`sequenceId`、`phaseStartedAt`、`phaseEndsAt`、`revision`、`result`（色名、二色、写真ID）、`previewColorId`
- 自画面の `displayOrder`（URL `/display/N` の N − 1）
- `prefers-reduced-motion` の値

同じ入力からは同じ画面を描く。再接続した画面はほかの画面と同じ位置から再開する。乱数は使わず、`sessionId` から作るハッシュ値を種にする。

### 2.2 パレットの色の並べ替え

風景色パレットの13色（仕様書6.2節）を同時に並べる場面では、`sessionId` のハッシュ値から並び順を決める。並び順は同じセッションの間は全画面で同じで、セッションごとに変わる。`sessionId` が `null` の場合は、色相順のパレットを5つずつ飛ばして巡る、色相が隣り合わない固定順 `vermilion, forest, indigo, amber, jade, rose, leaf, blue, orange, emerald, wisteria, gold, sky` を使う。

### 2.3 画面ごとの違い

画面ごとの違いは `displayOrder` だけから作る。質問中の破片の色は、`displayOrder` が1増えるごとに一区画ずらして見せる。色の並びは一問確定するたびに右へ一区画ずれるので、ある画面に見えていた色が右隣の画面へ移る。教室を歩くと、隣の画面に色が続いて見える。

### 2.4 イージング

- 出現と移動: `easeInOutSine`
- 結果色の広がり: `easeInOutSine`（縁のぼけ幅の分だけ遠くまで広げるため、序盤で一気に進む `easeOutCubic` では早く満ちて見える）
- 消える動き: `easeInSine`

### 2.5 基本色

| 用途                     | 色                       |
| ------------------------ | ------------------------ |
| 待機と質問の背景         | `#0B0B0B`（仕様書7.2.2） |
| 判定の暗転               | `#000000`                |
| 展示タイトル、iPadの文字 | `#E8E6E3`                |
| 補助文、無効表示         | `#8A8784`                |
| 線、無効な要素           | `#3A3836`                |

## 3. 展示ディスプレイ

### 3.1 `idle` と `intro`: 写真の巡回

仕様書7.2.3のとおり、背景 `#0B0B0B` に写真を一作品ずつ表示し、8秒枠の先頭1秒でクロスフェードする。この状態ではグラフィックスを描かない。待機中の主役は写真である。

`displayOrder >= P` の画面は、画面中央に展示タイトル「あなた色写真展」を `#E8E6E3` で表示する。文字の大きさは画面短辺の6%とし、ほかの要素を置かない。

`intro` では `idle` の巡回をそのまま続ける。`intro` 中に新しく接続した画面は、直前の `idle` の開始時刻を知らないので、`intro` の `phaseStartedAt` を巡回の基準にする。

### 3.1.1 `sequence`: 連動演出

`sequence` の見た目は、シーケンスごとのSvelteコンポーネントで書く（`src/client/sequences/<id>/Controller.svelte` と `Display.svelte`）。展示ディスプレイでは待機写真（3.1節）の巡回を続け、その上の全面にコンポーネントを重ねる。コンポーネントは写真を透かしても覆ってもよい。

コンポーネントにはpropsとして再生位置 `t`（補正済みサーバー時刻と `phaseStartedAt` の差。0から `durationMs` まで）、`durationMs`、`sessionId`、`reducedMotion` を渡し、展示ディスプレイ用には `displayOrder` も渡す。全画面の描画を同期させ、再接続しても同じ位置から続けられるよう、見た目はこれらの値だけから決める。乱数が要るときは `sessionId` から作り、`Math.random()` や端末の時計を直接使わない。reduced-motionの扱いもコンポーネントで決める。

再生が終わると次の段階へ切り替わる。`intro` は待機写真を表示し、`question` は待機写真から破片へ移る（reduced-motionでは即時に破片を表示する）ため、終わりの見た目は待機写真に戻しておく。各シーケンスのコンポーネントがあることは、production buildの検証で確かめる。

### 3.2 `question`: 巡る色の破片

構図: 三角形の破片の輪と床（4.4節の配置と動き）を描き、破片をパレットの13色で塗る。破片の色は重心の横位置で決まり、13色が等しい幅の区画を占める。画面の幅には2.5区画が並び、一画面に見える色は2〜3色になる。隣り合う色は区画の境目で溶け合う（区画の90%の幅）。明るい破片ほど色を白へ寄せ（最大35%）、重なりで濃淡を作る。背景は `#0B0B0B`。

区画の並び順は2.2節のとおり `sessionId` から決める。横位置 `x` の区画番号は次で求め、`colors[i]` は番号が `i` から `i + 1` の範囲を占める（8区画で一巡する）。

```text
区画番号 = x / 幅 × 2.5 − ずれ
ずれ = 基準角(sessionId) / 45° + revision − displayOrder
```

ずれは全画面で共通の式から求め、`revision` の変化時刻も共有するため、展示ディスプレイの色の並びはどの画面でも同じ時刻に同じだけ動く。破片は輪を公転し床を流れるので、一枚の破片は区画をまたぐたびに色を変える。

破片の位置は補正済みサーバー時刻から求めるので、全画面で同じ時刻に同じ位置になり、再接続した画面も同じ位置から再開する。

動き:

| 契機                                  | 動き                                                           | 所要時間                                            |
| ------------------------------------- | -------------------------------------------------------------- | --------------------------------------------------- |
| `question` に入る（`phaseStartedAt`） | 写真が消え、破片が透明から現れる                               | 写真の消失1.5秒、破片の出現3.0秒（0.6秒遅れて開始） |
| `revision` が増える（一問確定）       | 色の並びが右へ一区画ずれる。同時に輪の半径が8%広がり、元へ戻る | 6.0秒                                               |
| 常時                                  | 輪が150秒で一周し、床が左へ流れる（4.4節）                     | 4.4節のとおり                                       |

`revision` が増えた時刻は、サーバーが最後にiPad操作を受理した時刻 `phaseEndsAt - 5分` を使う（仕様書8.2節で `question` の `phaseEndsAt` は最終操作から5分後）。全画面が同じ時刻からずれ始め、途中で再接続した画面も同じ位置から再開する。

意図: 一問答えるたびに、すべての色が一つずつ隣へ移る。13色はいつも同じ面積で並び、どの色も強調しないので、回答がどの色へ近づいているかは読み取れない。展示ディスプレイには回答内容が届かないので、反応は「一問確定した」ことだけを伝える。「戻る」も `revision` を増やすため、同じ動きが起きる。

### 3.3 `judging`: 暗転

`judging` の `phaseStartedAt` から、破片が薄くなって消え（1.2秒、`easeInSine`）、背景が `#0B0B0B` から `#000000` へ沈む（1.2秒）。残りの0.8秒は黒のまま保つ。

意図: 全画面が一度静かに暗くなり、次に現れる色を待つ時間を作る。

### 3.4 `result`: 二色の出現

結果演出は `judging` の `phaseEndsAt`（= `result` の `phaseStartedAt`）に始まる。各画面は、AIが選んだ二色のうち自画面の色（`displayOrder` が偶数なら一色目、奇数なら二色目。仕様書7.2.4節）を見せる。最初の描画フレームで、すでにその色が起点から画面短辺の8%の位置まで見えている。全画面がこの時刻を補正済みサーバー時刻で待って切り替える（仕様書7.2.4節）。

演出は三段に分ける。

1. 広がり: 自画面の色の基準色（パレットの色そのもの）が、縁をぼかしたまま黒い画面を覆うまでにじみ広がる（下表の所要時間 `D`）。広がりは直線、帯、画面の縁のいずれかから測った距離で決め、円にならない。縁のぼけ幅は画面短辺の20%から75%へ広がり、縁はノイズでぼけ幅の±60%だけ揺れる。広がりの終わりには、揺れを含めても画面全体が基準色で塗りつぶされている。
2. 沈み: 全面が基準色から `backgroundColor` へ移る（`D` から1.0秒）。
3. 写真: 割り当てられた写真、またはタイポグラフィ表示の色名が現れる（`D + 0.4秒` から1.2秒）。

完了後は仕様書7.2.4のとおり、`backgroundColor` の全面に写真か色名だけが残る。

広がり方は次の8種類とし、パレットの13色へ、色相の近い色が同じ広がり方にならないよう割り当てる（`RESULT_FORMS`、仮の割り当て）。

| 広がり方       | 形                                                                                           | `D`   | 割り当てる色   |
| -------------- | -------------------------------------------------------------------------------------------- | ----- | -------------- |
| `openingBand`  | 画面の高さの中央を通る水平線から、上下へ色が開く                                             | 1.6秒 | vermilion      |
| `risingSlant`  | 右下の隅から、左へ傾いた前線が昇るように色が満ちる                                           | 1.8秒 | orange         |
| `meetingTides` | 左右の端から色が流れ込み、中央で溶け合う                                                     | 1.4秒 | amber          |
| `fallingTide`  | 上端から色が降りてくる                                                                       | 1.6秒 | gold、sky      |
| `risingTide`   | 下端から水位が上がるように色がせり上がる                                                     | 2.2秒 | leaf、indigo   |
| `closingFrame` | 画面の四辺から内側へ色が満ちていく（四辺からの距離をなめらかに合わせ、隅の折れ目を出さない） | 2.0秒 | forest、blue   |
| `sweepingTide` | 色が横へ流れ込む。偶数の `displayOrder` は左から、奇数は右から                               | 1.6秒 | emerald、rose  |
| `diagonalTide` | 左上の隅から右下の隅へ、斜めの前線で色がゆっくり伸びる                                       | 2.6秒 | jade、wisteria |

全画面が同じ時刻に始まる。二色の広がり方は異なりうるため、隣り合う画面で形と所要時間が変わることがある（`sweepingTide` は向きも画面ごとに変わる）。縁を揺らすノイズは結果開始時刻からの経過秒で流す。

結果開始後に接続または再接続した画面は、演出を再生せず完了状態を即時に表示する（仕様書7.2.4）。

### 3.5 管理画面からの表示確認（`previewColorId`）

`idle` で `previewColorId` が設定されている間は、全画面にその色の結果完了状態（`backgroundColor` とタイポグラフィの色名）を演出なしで表示する。写真はセッションごとに選ぶため、表示確認では見せない。

### 3.6 `idle` へ戻るとき

`result` または強制リセットから `idle` へ戻ると、それまでの画面が1.0秒で消え、待機の写真が現れる。

## 4. iPad

### 4.1 共通

- 背景 `#FFFFFF`、文字 `#000000`。主操作のボタンは `#000000` の塗りに `#FFFFFF` の文字、角丸なしの帯形とする。
- 待機画面の「はじめる」のボタンは、押している間だけ0.96倍に縮み、矢印が右へ6px動く。縮小と移動は120msで行い、離すと同じ時間で戻す。`prefers-reduced-motion: reduce` が有効なときは時間をかけずに切り替える。
- 文字は抽象グラフィックスの上へ重ねない。

### 4.2 状態ごとの構図

| 状態       | 構図                                                                                                                     | 動き                                        |
| ---------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------- |
| `idle`     | 中央に歓迎文言（`welcomeMessage`）と「はじめる」のボタン。ボタンは文字の右に矢印を置く                                   | 押している間、縮小と矢印の移動（4.1節）     |
| 受付停止   | 中央に展示タイトルと受付停止の案内文言を表示し、開始ボタンを置かない                                                     | なし                                        |
| `sequence` | 中央にシーケンスの `Controller.svelte` を表示する（3.1.1節）                                                             | コンポーネントで決める                      |
| `intro`    | 進捗バー、見出し、ニックネームの入力欄と「→」ボタンを表示する                                                            | なし                                        |
| `question` | 上部に進捗バー。中央に質問文と入力（4.3節）、下部に「戻る」「次へ」                                                      | 確定待ちのつまみとピンの点線が回る（4.3節） |
| `judging`  | 中央に「あなたの色を選んでいます」だけを置く                                                                             | なし                                        |
| `result`   | 一色目の `backgroundColor` の全面。二色の混色の円（色面）、色名、二色の名前、読み取り、QRコード、結果URL、「最初に戻る」 | 色面の円が20%の大きさから広がる（1.4秒）    |

`result` の色面は、二色を直線補間した13段のグラデーション（仕様書6.2節）で塗った円とする。縦向きは円、色名、二色の名前、読み取り、QRコード、URL、ボタンを縦に並べる。横向きは左に円と文字、右にQRコードとボタンを置く。QRコードは仕様書10.3節のとおり白地に黒で描き、結果の色で着色しない。

### 4.3 入力の状態

仕様書7.1節の5状態を、スライダーと2Dマップではつまみやピンの形、枠、ラベルで見分ける。色だけで区別しない。つまみとピンはスナップせず指に付いて動くため、位置の移動は補間せず、大きさだけを120msで変化させる。

スライダーは、画面全体を縦の仕切り線で左右に分ける。仕切り線の左の領域に左の語（`leftLabel`）、右の領域に右の語（`rightLabel`）を置き、広い側の語を選んでいるとみなす。回答が左の語に近いほど仕切り線は右へ寄り、左の語が大きく、右の語が小さくなる（文字の大きさは左右が同じ広さのとき24px、端では広い側が約53px、狭い側が13px）。狭い側の語も読める幅を残すため、仕切り線は画面幅の15%から85%の範囲で動く。仕切り線の上下中央には、左右の矢印が付いたつまみを置く。進捗バーと質問文を含め、画面のほぼ全域で触れた指の位置へ仕切り線が動く。そのため、語の上をタップすると、その語の側は狭くなり、回答は反対側の語へ寄る。押し間違いで回答が変わらないよう、下部のボタン列は触れても仕切り線を動かさない。仕切り線は質問文と重なる上部を薄くする。質問文の下には、状態に応じたラベルを置く。

| 状態                   | つまみ                  | 枠           | 質問文の下のラベル                                             |
| ---------------------- | ----------------------- | ------------ | -------------------------------------------------------------- |
| 未回答                 | 画面中央の直径40pxの円  | 破線         | 「しっくりくる位置に動かしてください。真ん中でも大丈夫です。」 |
| 操作中                 | 直径48pxの円            | 太い実線     | 最も近い回答位置の補助文                                       |
| 確定待ち               | 直径40pxの円            | 点線が回る輪 | 「送信しています」                                             |
| 確定済み（戻ったとき） | 直径40pxの円            | 二重線       | 「回答済み: {補助文}」                                         |
| 無効                   | 直径40pxの円、`#3A3836` | 枠なし       | 「操作できません」                                             |

2Dマップは、ピンの形、枠、平面下のラベルを次のとおり表す。

| 状態                   | ピン                           | 枠           | 平面下のラベル                   |
| ---------------------- | ------------------------------ | ------------ | -------------------------------- |
| 未回答                 | 中央に薄く表示した直径28pxの円 | 破線         | 「さわって場所を選んでください」 |
| 操作中                 | 直径40pxの円                   | 太い実線     | ピンを含む区画の補助文           |
| 確定待ち               | 直径28pxの円                   | 点線が回る輪 | 「送信しています」               |
| 確定済み（戻ったとき） | 直径32pxの円                   | 二重線       | 「回答済み: {補助文}」           |
| 無効                   | 直径28pxの円、`#3A3836`        | 枠なし       | 「操作できません」               |

単選択と複数選択は、選択肢の塗りと印、選択肢の下のラベルで見分ける。

| 状態                   | 選んだ選択肢                                       | 選んでいない選択肢                         | 選択肢の下のラベル                                  |
| ---------------------- | -------------------------------------------------- | ------------------------------------------ | --------------------------------------------------- |
| 未回答                 | なし                                               | 白地に黒の実線の枠                         | 「一つ選んでください」「2つまで選んでください」など |
| 操作中                 | 黒の塗り、印に点（単選択）かチェック（複数選択）   | 同上。上限に達したら薄く表示               | 選んだ選択肢（単選択）、選んだ数（複数選択）        |
| 確定待ち               | 黒の塗りと印を保ち、印の枠を点線にする（回さない） | 薄く表示                                   | 「送信しています」                                  |
| 確定済み（戻ったとき） | 黒の塗りと印を保ち、枠の内側に白い線を重ねた二重線 | 白地に黒の実線の枠。上限に達したら薄く表示 | 「回答済み: {選んだ選択肢}」                        |
| 無効                   | 黒の塗りと印を保ち、枠を `#3A3836` にする          | 枠を `#3A3836` にして薄く表示              | 「操作できません」                                  |

### 4.4 破片の配置

半透明の細長い三角形（破片）で作る輪と床の配置と動きを、展示ディスプレイの質問中（3.2節）の仕様として次のとおり決める（`src/shared/shards.ts`）。輪と床の両方をパレットの13色で描く。

- 輪: 画面中央を中心とし、半径は画面短辺の38%。破片130枚を半径の±20%の範囲へ中心線付近ほど密に散らし、輪の内側を空ける。破片は輪の接線方向を向く。
- 床: 画面の高さの78%から下端まで、破片110枚を下端ほど密に置く。輪の下端は床に重なる。
- 破片: 長さは輪の破片が輪の半径の14〜34%、床の破片が画面短辺の7〜18%。明るさ150〜255、不透明度30〜75%。
- 動き: 輪は時計回りに150秒（破片ごとに±20%）で一周し、半径方向に14〜32秒周期でわずかに揺れる。破片は40〜100秒周期でゆっくり自転する。床は輪の下端と同じ向き（左）へ210秒で画面幅を流れ、端で反対側へ回り込む。
- 初期配置は固定の種から作る擬似乱数で決め、位置は3.2節のとおり時刻から求める。

## 6. `prefers-reduced-motion: reduce`

動きを止めても状態が伝わるように、各状態を色面の切り替えと静止した構図で表す。

| 状態                             | 通常                               | reduced-motion                                                                          |
| -------------------------------- | ---------------------------------- | --------------------------------------------------------------------------------------- |
| 展示 `idle`                      | 1秒のクロスフェード                | 8秒ごとに即時切り替え（仕様書7.2.3）                                                    |
| 展示 `sequence`                  | コンポーネントで決める（3.1.1節）  | コンポーネントで決める。仮データの `opening` は暗転を即時に切り替え、光の帯を流さない   |
| 展示 `question` 開始             | 破片が透明から現れる               | 破片を初期配置のまま即時に表示                                                          |
| 展示 `question` 一問確定         | 色の並びが6秒かけて一区画ずれる    | 色の並びを一区画ずらした構図へ即時に切り替える。破片は動かさない                        |
| 展示 `judging`                   | 1.2秒で暗転                        | 即時に `#000000`                                                                        |
| 展示 `result`                    | 色が広がり、沈み、写真が現れる     | 基準色の全面を1.6秒表示し、`backgroundColor` と写真（または色名）の完了状態へ切り替える |
| 展示 `idle` へ戻る               | 1秒で消える                        | 即時切り替え                                                                            |
| iPad `sequence`                  | コンポーネントで決める（3.1.1節）  | コンポーネントで決める。仮データの `opening` は文言をフェードせず即時に切り替える       |
| iPad 全状態（`sequence` を除く） | 色面の広がり、待機画面の破片の動き | すべて静止。待機画面の破片は初期配置のまま止める                                        |

reduced-motionでの基準色→完了状態の切り替えは一回だけで、繰り返さない。

## 7. 描画方式

- 展示ディスプレイの塗りとグラデーションは全面の `<canvas>` 一枚に描く。このcanvasはなだらかなグラデーションと全面の塗りしか描かないので、CSS画素の半分の解像度で描いて引き伸ばし、フラグメントシェーダーの負荷を `devicePixelRatio` に依存させない。写真とタイポグラフィはcanvasの上のDOM要素とし、写真には仕様書7.2.2のとおりフィルターをかけない。
- 質問中の破片は、その上に重ねたもう一枚の `<canvas>` へcanvas 2Dで描く。破片の輪郭を見せるため、こちらはCSS画素の2倍までの解像度で描く。
- 塗りとグラデーションのcanvasはWebGL2のフラグメントシェーダーで描く（`src/client/display/renderer.ts`）。一フレームの描画内容（塗り、結果色のにじみ）を一度に合成し、グラデーションの部分だけに1階調未満のディザをかけて暗い色の段差を消す。全面の塗りの部分は指定色をそのまま出力する。
- WebGL2を使えない環境では、canvas 2Dの線形グラデーションで結果色のにじみを近似する（ノイズの揺れは描かない）。
- 描画結果は次の描画まで保持し（`preserveDrawingBuffer`）、テストは二枚のcanvasを2Dのcanvasへ重ねて写して画素を読む。
- 毎フレームの描画内容は純粋関数で計算し、描画処理と分ける。純粋関数は同じ入力に同じ結果を返すことを単体テストで確認する。
- 動きのない状態（写真表示中、`result` 完了後）はcanvasを描き直さない。
