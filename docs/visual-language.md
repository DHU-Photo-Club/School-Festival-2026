# あなた色写真展 - 演出のビジュアル言語

本書は、仕様書 `docs/README.md` が定めていない展示ディスプレイとiPadの演出の見た目を定める。演出の実装は本書に従い、仕様書と食い違う場合は仕様書を優先する。

## 1. 原則

- 主役は写真作品と、選ばれた「色」である。グラフィックスは写真を見る前後の時間だけに現れ、写真の表示中は背景色以外を描かない。
- 画面を構成する要素は、色面、グラデーション（色のにじみ）、ゆっくりした動きだけとする。iPadではこれに円、帯、弧を加える。具体的な物、人、風景、文字記号を描かない（仕様書が定める色名、展示タイトル、操作文字を除く）。
- 一つの画面で同時に見える色面は、背景を除いて3面以下とする。
- 展示ディスプレイの色は、輪郭のある形ではなく、背景へなだらかに溶けるグラデーションで表す。形は直線、帯、画面の縁からの距離だけで作り、円や点からの距離を使わない。縁はノイズでゆっくり揺らし、図形の輪郭に見せない。iPadの形の縁は塗りの境界だけで表す。影、半透明パネルは使わない。
- 動きは来場者が視界の端で変化に気づく程度の速さにする。一つの動きの所要時間は1.4秒以上とし、繰り返す動きの周期は12秒以上とする。
- 明るさが短い間隔で上下する演出（強い高速点滅）を使わない。明度の大きな切り替えは一回の体験の中で「判定の暗転」と「結果色の出現」の二回に限る。

### 1.1 使わない表現

写真作品と競合し、スクリーンセーバーや汎用の背景に見えるため、次を使わない。

- 発光するパーティクルの群れ
- ネオンのグロー
- すりガラス風のぼかしパネル
- 色の配置に意味がなく、色がばらばらに混ざり合いながら画面全体を流れ続けるメッシュグラデーション（展示ディスプレイのにじみは、色の位置を2.2節と3.2節の並びで決め、ノイズは境目を揺らすだけにする）
- ランダムに漂う小さな点
- 紫から青への定番グラデーション
- 色相順に並んだ8色の帯（虹に見えるため。8色を並べるときは2.2節の並べ替えを使う）
- 中心から時計回りに一周する扇形のワイプ（スライドショーの定番トランジションに見えるため。最初の実装で violet に使い、作り直した）

実装を見て別の定番表現に寄っていた場合は、この一覧へ追加して作り直す。

## 2. 共通の決め方

### 2.1 時刻と決定性

展示ディスプレイの描画は、毎フレーム次の値だけから計算する。

- 補正済みサーバー時刻 `t`（`performance.timeOrigin + performance.now() + 時刻補正値`）
- 受信状態の `sessionId`、`phase`、`phaseStartedAt`、`phaseEndsAt`、`revision`、`resultColorId`、`previewColorId`
- 自画面の `displayOrder`（登録時に振られた画面ID `display-N` の N − 1）
- `prefers-reduced-motion` の値

同じ入力からは同じ画面を描く。再接続した画面はほかの画面と同じ位置から再開する。乱数は使わず、`sessionId` から作るハッシュ値を種にする。

### 2.2 8色の並べ替え

8色を同時に並べる場面では、`sessionId` のハッシュ値から並び順を決める。並び順は同じセッションの間は全画面で同じで、セッションごとに変わる。`sessionId` が `null` の画面（iPadの待機）は、色相が隣り合わない固定順 `red, cyan, yellow, violet, green, magenta, blue, orange` を使う。

### 2.3 画面ごとの違い

画面ごとの違いは `displayOrder` だけから作る。質問中の色のにじみは、`displayOrder` が1増えるごとに一区画ずらして見せる。にじみは一問確定するたびに右へ一区画ずれるので、ある画面に見えていた色が右隣の画面へ移る。教室を歩くと、隣の画面に色が続いて見える。

### 2.4 イージング

- 出現と移動: `easeInOutSine`
- 結果色の広がり: `easeInOutSine`（縁のぼけ幅の分だけ遠くまで広げるため、序盤で一気に進む `easeOutCubic` では早く満ちて見える）
- 消える動き: `easeInSine`

### 2.5 基本色

| 用途 | 色 |
| --- | --- |
| 待機と質問の背景 | `#0B0B0B`（仕様書7.2.2） |
| 判定の暗転 | `#000000` |
| 展示タイトル、iPadの文字 | `#E8E6E3` |
| 補助文、無効表示 | `#8A8784` |
| 線、無効な区画 | `#3A3836` |

## 3. 展示ディスプレイ

### 3.1 `idle` と `intro`: 写真の巡回

仕様書7.2.3のとおり、背景 `#0B0B0B` に写真を一作品ずつ表示し、8秒枠の先頭1秒でクロスフェードする。この状態ではグラフィックスを描かない。待機中の主役は写真である。

`displayOrder >= P` の画面は、画面中央に展示タイトル「あなた色写真展」を `#E8E6E3` で表示する。文字の大きさは画面短辺の6%とし、ほかの要素を置かない。

`intro` では `idle` の巡回をそのまま続ける。`intro` 中に新しく接続した画面は、直前の `idle` の開始時刻を知らないので、`intro` の `phaseStartedAt` を巡回の基準にする。

### 3.2 `question`: 巡る色のにじみ

構図: 8色を横に並べた色の帯を、画面の下側から上へにじませる。色は横位置で決まり、8色が等しい幅の区画を占める。画面の幅には2.5区画が並び、一画面に見える色は2〜3色になる。隣り合う色は区画の境目で溶け合い（区画の90%の幅）、高さが上がるほど境目を右へ少し倒す（画面の高さで0.35区画）。明るさは画面の下端から高さの40%の位置を山とし、上へは画面短辺の0.48×0.8倍、下へは0.48×1.8倍の幅で背景 `#0B0B0B` へ溶ける。輪郭は描かない。

区画の並び順は2.2節のとおり `sessionId` から決める。横位置 `x` の区画番号は次で求め、`colors[i]` は番号が `i` から `i + 1` の範囲を占める（8区画で一巡する）。

```text
区画番号 = x / 幅 × 2.5 − ずれ
ずれ = 基準角(sessionId) / 45° + revision − displayOrder
```

ずれはiPadの輪の回転角（4.1節）を区画数で表した値なので、展示ディスプレイのにじみはiPadの輪と同じ時刻に同じだけ動く。

色の境目と明るさの山は、画面短辺ほどの大きな模様のノイズで揺らす（区画番号で±0.7、高さで帯の幅の±45%、明るさで±20%）。ノイズは `question` の `phaseStartedAt` からの経過秒で流すので、全画面で同じ時刻に同じ揺れになる。ノイズの模様は一秒に画面短辺の約2%しか動かず、繰り返さない。

動き:

| 契機 | 動き | 所要時間 |
| --- | --- | --- |
| `question` に入る（`phaseStartedAt`） | 写真が消え、にじみの幅と明るさが0から広がって現れる | 写真の消失1.5秒、にじみの出現3.0秒（0.6秒遅れて開始） |
| `revision` が増える（一問確定） | にじみが右へ一区画ずれる。同時ににじみの幅が8%広がり、元へ戻る | 6.0秒 |
| 常時 | 明るさの山の高さが±1.5%の幅で呼吸し、境目がノイズで揺れる | 呼吸の周期12秒 |

`revision` が増えた時刻は、サーバーが最後にiPad操作を受理した時刻 `phaseEndsAt - 5分` を使う（仕様書8.2節で `question` の `phaseEndsAt` は最終操作から5分後）。全画面が同じ時刻からずれ始め、途中で再接続した画面も同じ位置から再開する。

意図: 一問答えるたびに、すべての色が一つずつ隣へ移る。8色はいつも同じ面積で並び、どの色も強調しないので、回答がどの色へ近づいているかは読み取れない。展示ディスプレイには回答内容が届かないので、反応は「一問確定した」ことだけを伝える。「戻る」も `revision` を増やすため、同じ動きが起きる。

### 3.3 `judging`: 暗転

`judging` の `phaseStartedAt` から、にじみが狭く薄くなって消え（1.2秒、`easeInSine`）、背景が `#0B0B0B` から `#000000` へ沈む（1.2秒）。残りの0.8秒は黒のまま保つ。

意図: 全画面が一度静かに暗くなり、次に現れる色を待つ時間を作る。

### 3.4 `result`: 結果色の出現

結果演出は `judging` の `phaseEndsAt`（= `result` の `phaseStartedAt`）に始まる。最初の描画フレームで、すでに結果色が起点から画面短辺の8%の位置まで見えている。このフレームが同期計測の基準になる（仕様書8.7節）。

演出は三段に分ける。

1. 広がり: 結果色の基準色が、縁をぼかしたまま黒い画面を覆うまでにじみ広がる（下表の所要時間 `D`）。広がりは直線、帯、画面の縁のいずれかから測った距離で決め、円にならない。縁のぼけ幅は画面短辺の20%から75%へ広がり、縁はノイズでぼけ幅の±60%だけ揺れる。広がりの終わりには、揺れを含めても画面全体が基準色で塗りつぶされている。
2. 沈み: 全面が基準色から `backgroundColor` へ移る（`D` から1.0秒）。
3. 写真: 割り当てられた写真、またはタイポグラフィ表示の色名が現れる（`D + 0.4秒` から1.2秒）。

完了後は仕様書7.2.4のとおり、`backgroundColor` の全面に写真か色名だけが残る。

8色の広がり方は、仕様書6.2節の「写真の方向性」から決める。

| 色 | 広がり方 | `D` | 写真の方向性との対応 |
| --- | --- | --- | --- |
| red | 画面の高さの中央を通る水平線から、上下へ色が開く | 1.6秒 | 熱、生命、近距離。中心から近く満ちる |
| orange | 右下の隅から、左へ傾いた前線が昇るように色が満ちる | 1.8秒 | 夕方、親密さ、温度。低い位置からの暖かさ |
| yellow | 上端から色が降りてくる | 1.6秒 | 光、開放感、軽さ。上から差す光 |
| green | 下端から水位が上がるように色がせり上がる | 2.2秒 | 植物、水、静かな成長。ゆっくり伸びる |
| cyan | 色が横へ流れ込む。偶数の `displayOrder` は左から、奇数は右から | 1.6秒 | 透明感、風、反射。隣の画面と鏡写しになる |
| blue | 画面の四辺から内側へ色が満ちていく（四辺からの距離をなめらかに合わせ、隅の折れ目を出さない） | 2.0秒 | 夜、奥行き、集中。中心へ向かう |
| violet | 左上の隅から右下の隅へ、斜めの前線で色がゆっくり伸びる | 2.6秒 | 影、余韻、非日常。影が伸びるように最も長く余韻を残す |
| magenta | 左右の端から色が流れ込み、中央で溶け合う | 1.4秒 | 華やかさ、遊び、躍動。最も軽快 |

全画面が同じ時刻に同じ形で始まり、同じ時刻に終わる（cyanだけは向きが画面ごとに変わる）。縁を揺らすノイズは結果開始時刻からの経過秒で流す。

結果開始後に接続または再接続した画面は、演出を再生せず完了状態を即時に表示する（仕様書7.2.4）。

### 3.5 管理画面からの表示確認（`previewColorId`）

`idle` で `previewColorId` が設定されている間は、その色の結果完了状態（`backgroundColor` と割り当て写真、またはタイポグラフィ）を演出なしで表示する。

### 3.6 `idle` へ戻るとき

`result` または強制リセットから `idle` へ戻ると、それまでの画面が1.0秒で消え、待機の写真が現れる。

## 4. iPad

### 4.1 共通

- 背景 `#0B0B0B`、文字 `#E8E6E3`。主操作のボタンは `#E8E6E3` の塗りに `#0B0B0B` の文字、角丸の帯形とする。
- 画面の象徴として、展示ディスプレイの色のにじみと同じ8色の並びを、8区画の小さな輪（以下「輪」）にして置く。輪の区画の並び順と回転は2.2節、3.2節と同じ計算を使う（`displayOrder` の項は0）。
- 文字は抽象グラフィックスの上へ重ねない。

### 4.2 状態ごとの構図

| 状態 | 構図 | 動き |
| --- | --- | --- |
| `idle` | 画面上部に直径 `min(56vmin, 420px)` の輪。その下に展示タイトルと「診断をはじめる」 | 輪が240秒で一周する |
| 受付停止 | 輪の全区画を `#3A3836` にする。案内文を表示し、開始ボタンを置かない | なし |
| `intro` | 輪を直径 `min(28vmin, 200px)` に縮め、所要時間と診断の位置づけを表示する | 輪が240秒で一周する |
| `question` | 上部に直径64pxの輪と `3 / 7`。中央に質問文、下部にスライダーと「戻る」「次へ」 | `revision` が増えると輪が一区画回る（1.4秒） |
| `judging` | 中央に輪だけを置き、その下に「あなたの色を選んでいます」 | 輪の帯が細くなり、中心へ縮んで消える（1.6秒） |
| `result` | `backgroundColor` の全面。基準色の円（色面）、色名、メッセージ、QRコード、結果URL、「最初に戻る」 | 色面の円が20%の大きさから広がる（1.4秒） |

`result` の色面は基準色の円とする。縦向きは円、色名、メッセージ、QRコード、URL、ボタンを縦に並べる。横向きは左に円と文字、右にQRコードとボタンを置く。QRコードは仕様書10.3節のとおり白地に黒で描き、結果色で着色しない。

| 状態 | つまみ | 枠 | トラック下のラベル |
| --- | --- | --- | --- |
| 未回答 | 中央に薄く表示した直径28pxの円 | 破線 | 「動かして選んでください」 |
| 操作中 | 直径40pxの円 | 太い実線 | 選択中の位置の補助文 |
| 確定待ち | 直径28pxの円 | 点線が回る輪 | 「送信しています」 |

## 6. `prefers-reduced-motion: reduce`

動きを止めても状態が伝わるように、各状態を色面の切り替えと静止した構図で表す。

| 状態 | 通常 | reduced-motion |
| --- | --- | --- |
| 展示 `idle` | 1秒のクロスフェード | 8秒ごとに即時切り替え（仕様書7.2.3） |
| 展示 `question` 開始 | にじみが広がって現れる | にじみを静止した状態で即時に表示 |
| 展示 `question` 一問確定 | にじみが6秒かけて一区画ずれる | にじみを一区画ずらした構図へ即時に切り替える。呼吸せず、ノイズも流さない |
| 展示 `judging` | 1.2秒で暗転 | 即時に `#000000` |
| 展示 `result` | 色が広がり、沈み、写真が現れる | 基準色の全面を1.6秒表示し、`backgroundColor` と写真（または色名）の完了状態へ切り替える |
| 展示 `idle` へ戻る | 1秒で消える | 即時切り替え |
| iPad 全状態 | 輪の回転、縮小、色面の広がり | すべて静止。`judging` は細い輪と文言だけを表示する |

reduced-motionでの基準色→完了状態の切り替えは一回だけで、繰り返さない。

## 7. 描画方式

- 展示ディスプレイのグラフィックスは全画面の `<canvas>` 一枚に描く。canvasはなだらかなグラデーションと全面の塗りしか描かないので、CSS画素の半分の解像度で描いて引き伸ばし、フラグメントシェーダーの負荷を `devicePixelRatio` に依存させない。写真とタイポグラフィはcanvasの上のDOM要素とし、写真には仕様書7.2.2のとおりフィルターをかけない。
- canvasはWebGL2のフラグメントシェーダーで描く（`src/client/display/renderer.ts`）。一フレームの描画内容（塗り、色のにじみ、結果色のにじみ）を一度に合成し、グラデーションの部分だけに1階調未満のディザをかけて暗い色の段差を消す。全面の塗りの部分は指定色をそのまま出力する。
- WebGL2を使えない環境では、canvas 2Dの線形グラデーションでにじみを近似する（ノイズの揺れは描かない）。
- 描画結果は次の描画まで保持し（`preserveDrawingBuffer`）、テストは2Dのcanvasへ写して画素を読む。
- 毎フレームの描画内容は純粋関数で計算し、描画処理と分ける。純粋関数は同じ入力に同じ結果を返すことを単体テストで確認する。
- 動きのない状態（写真表示中、`result` 完了後）はcanvasを描き直さない。
