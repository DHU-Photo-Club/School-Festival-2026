# 実装の進捗

作業を再開するときは、この記録と `git log` を確認する。

## 完了したこと

- `docs/visual-language.md` で演出のビジュアル言語を決定
- 土台: pnpm、Vite 8、Svelte 5、Cloudflare Vite plugin、Vitest、Playwright、TypeScript 6（`svelte-check` が TypeScript 7 に未対応のため6系に固定）
- 共通モジュール（`src/shared/`）: 型、判定、状態遷移、メッセージ検証、写真割り当て、時刻補正、演出の純粋関数、データ検証、結果URL
- 仮データ（`src/data/`）: 色、質問と配点、開催情報
- 写真: 提供された12点（原本 `photos/originals/`）から `pnpm export-photos` で表示用のAVIFとJPEGを書き出した。生成した仮写真（`kari-*`）は削除
- Durable Object（`src/worker/`）: WebSocket Hibernation、alarm、役割別の配信
- 画面（`src/client/`）: iPad、展示ディスプレイ、写真用、管理画面、結果ページ
- production build時の検証（`scripts/`）: `PUBLIC_ORIGIN`、`RESULTS_PUBLISHED_UNTIL`、色・診断・写真定義、写真ファイル
- 単体テスト（`tests/unit/`）、E2Eテスト（`tests/e2e/`）
- `sequence`: iPadと展示ディスプレイの演出を時間経過で自動で進める段階。`intro` または `question` の直前に再生する。ID、再生後に入る段階（`before`）、再生時間は `src/data/sequences.ts`、見た目は `src/client/sequences/<id>/` のコンポーネントで書く（仮データ。下記「判断に迷った点」6）
- 展示3画面とiPadで一回の診断を通し、通常とreduced-motionの各状態のスクリーンショットを `docs/visual-language.md` と比較
  - violet の「時計回りに一周する扇形」がスライドショーのワイプに見えたため、使わない表現に加え、隅から伸びる円に変更
  - iPadの質問画面で質問文とスライダーが離れすぎていたため、中央にまとめた
- フレーム時間: GPU（D3D11）を使うChromiumで、1920×1080 と 3840×2160 の両方で待機、輪の出現、回転、判定から結果まで60fps、25msを超えるフレームなし。GPUなし（SwiftShader）では3840×2160の半透明レイヤー合成区間で47〜53fps
- **一回きりの学内展示に合わせて仕組みを削った（2026-11-20、ユーザーの指示）**。仕様書も同じ内容に書き換えた。
  - 端末のペアリング、Cookieの端末セッション、管理セッションを削除した。認証は Cloudflare Access に任せる（仕様書14章）。端末はURLで役割と画面番号を決める（`/display/2` など）
  - 再送、冪等性の記録、`expectedRevision`、エラーコード、close code、`hello`、プロトコルのバージョンを削除した。操作は状態機械が現在状態で受け付けるかを判断し、二度目の同じ操作は拒否される
  - 操作端末の占有と引き継ぎを削除した。どのiPadからでも操作できる
  - 結果同期の計測（`resultStarted`）、先読みの報告、時刻同期精度の報告、QRコード生成失敗の通知を削除した。時刻補正は直近6回の `ping` のうち往復が最も短い計測を使う
  - 管理画面は展示状態、表示確認、接続中の端末一覧の3パネルにした
  - 旧仕様書13章の性能測定と、実機の測定ログを求める受け入れ条件を削除した

- **質問の入力方式を4種類にした（2026-11-21、ユーザーの指示）**。単選択（`single`）、複数選択（`multiple`）、スライダー（`slider`）、2Dマップ（`map`）。質問定義は `kind` で分ける判別共用体、回答は、単選択が選択肢ID、複数選択が選択肢IDの配列、スライダーが0〜1の位置、2Dマップが `{ x, y }` の位置。回答の検証・配点・候補の列挙は `src/shared/answer.ts`。iPadの入力は `ChoiceList.svelte`（単選択と複数選択）、`MapPad.svelte`、`Slider.svelte`。入力方式を試すため、仮データのうち「時間帯」の質問を単選択、「場所」の質問を2Dマップ、「音」の質問を複数選択（6択から1〜2個）に変えた。コードレビューの指摘を受け、変更前に保存した回答のうち定義に合わないものを除く処理（`reconcileState`）、2Dマップの読み上げとキーボード操作用のラジオボタン、補助文の有無と配点が整数であるかの検証、`pnpm distribution` のパターン数の上限（5,000万通り）を加えた。その後、スライダーと2Dマップのスナップをやめ、位置に応じて近くの配点を距離で混ぜる方式にした（2026-11-21、ユーザーの指示。下記「判断に迷った点」10）。この変更のコードレビューを受け、分布の集計を区間の中点で数える方式に改め、スライダーにも読み上げとキーボード操作用のラジオボタンを加えた。スライダーの見えない `<input type="range">` はどの方法でも操作できなかったため、トラックの線を描くだけの `span` に置き換えた。
- **スライダーを画面全体の仕切り線にした（2026-11-21、ユーザーの指示）**。画面全体を縦の仕切り線で左右に分け、広い側の語を選んでいるとみなす。回答が左の語に近いほど仕切り線は右へ寄り、広い側の語を大きく、狭い側の語を小さく表示する。回答の値（左端0から右端1）と配点はそのまま。仕切り線の位置と回答の値の変換は `src/client/controller/split.ts`。見た目は `docs/visual-language.md` 4.3節。

## 判断に迷った点

ユーザーの判断が必要な点。実装はそれぞれ下記の仮の判断で進めている。

1. **`intro` 中に新しく接続した展示ディスプレイの待機巡回の基準時刻**。展示ディスプレイへ配信する状態には `idle` の開始時刻が残らないため、`intro` の `phaseStartedAt` を基準にしている。
2. **結果開始後に接続した展示ディスプレイの写真**。演出を再生しない画面は、割り当て写真の読み込みが終わった時点で写真か色名表示かを決め、以後は変えない。
3. **配点の偏り**。仮の配点で78,125通りの分布は最小10.85%（green）から最大14.43%（blue）。「極端な偏り」の基準が仕様書にないため、テストは全色が一度は出ることだけを確かめている（`pnpm distribution` で分布を表示）。
4. **仮の `PUBLIC_ORIGIN` でもproduction buildが通る**。ビルド時に確かめられるのはHTTPS、末尾スラッシュなし、`dpc-school-festival.<subdomain>.workers.dev` の形までで、subdomainが実在するかはアカウント情報がないと確かめられない。仮値 `tbd-subdomain` のままデプロイしないこと。
5. **写真の結果色の割り当て（仮）**。提供された12点の `resultColorId`、各色の代表画像、`shareAllowed`、`creditName`、`idleOrder` は、写真の主題から仮に決めた値（`src/data/photos.ts`）。写真担当による決定が必要。現在の割り当て: red `sdi1218-3`、orange `sdi0743`、yellow `sdi1092-2`、green `sdi0225` `sdi0776`、cyan `sdi0565-2` `sdi1091`、blue `sdi1195-3` `sdi1134-2`、violet `sdi1031-2` `sdi1163-3`、magenta `sdi1070-2`。各色1〜2点のため、3画面構成では写真のない画面が色名表示になる。
6. **`sequence` の仮データ**。「はじめる」の後に再生する演出の内容は未定のため、仮の `opening`（3.6秒）を `intro` の前に置いた。再生中はiPadに操作手段を置かず、止めるには管理画面の強制リセットを使う。
7. **写真の長辺**。表示用は原本の寸法（長辺2048px）のまま書き出している。4Kディスプレイでは拡大表示になる。
8. **原本の管理**。`photos/originals/` はリポジトリへコミットしていない。原本をリポジトリで管理するか、別の場所に保管するかの決定が必要。
9. **Cloudflare Access のパス別の除外**。仕様書14章では、`workers.dev` 全体を Access で保護し、`/result`、`/assets`、`/photos`、`/fonts` を Bypass のアプリケーションで外す手順にした。実際のアカウントでの設定は未確認。開場前の手順4で、ログインしていない端末から結果ページが開けて、`/` と `/admin` が開けないことを必ず確かめる。
10. **入力方式の仮の判断**。スライダーは5段階の回答位置に、2Dマップは3×3の区画の中心に配点を置き、それ以外の位置では近くの配点を距離で混ぜる（2Dマップは双線形補間）。2Dマップを5×5にすると配点の定義が25区画に増えるため3×3にした。複数選択は選んだ選択肢の配点を合計するため、選ぶ数でその問の重みが変わる。仮データでは各選択肢を1点、選択数の上限を2個にして、他の問（最大2点）と釣り合わせた。位置が連続値になったため、分布の集計はスライダーを8区間、2Dマップを9×9区間に分け、各区間の中点で数える（27,869,184通り、約2秒）。分布は最小5.01%（red）から最大18.16%（blue）。区間を細かくしても各色の割合の変化は1ポイント前後に収まる。red と violet が少なく blue が多い偏りは、配点を調整するときに見直す。`docs/進行.md` の「全部で９つ」という記述に合わせた問数の変更は、本文が決まってから行う。
