- **iPadの質問の入れ替えを加えた（2026-11-24、ユーザーの指示）**。「次へ」「戻る」で質問が切り替わると、前の質問が要素ごとに少しずつ遅れて、画面の奥へ縮んでぼけながら落ちて消え、その要素がすべて落ちきってから、次の質問が要素ごとに少しずつ遅れて、画面の手前から拡大されてぼけた状態で降りてきて、画面に貼り付く（入れ替え全体で3320ms）。最初は横へずれて入れ替わる動きで作り、同日、ユーザーの指示で手前から降りてくる動きに変え、さらに要素ごとに開始をずらし、次の質問の各要素が不透明になるまでの時間を600msにした。その後、前の質問もその場で消えるのではなく、同じような動きで同時に奥へ落ちるようにした。さらに、動きを大きく（手前の拡大は1.4倍から1.8倍、奥の縮小は0.7倍から0.5倍、ぼかしは18pxから24px）、かつゆっくりに（拡大縮小とぼかしは900msから1300ms、不透明度の変化は600msから900ms）し、前の質問が落ち始めてから次の質問が降り始めるまで300msの間をおいた。続けて、前の質問が落ちて消える動きのイージングを、イーズアウトからイーズイン（`easeInSine` と同じ曲線）に変え、透明になるまでの時間を落ちる動きと同じ1300msにした（900msのままだと、イーズインのためまだ大きく動いていないうちに透明になり、落ちる動きが見えなくなるため）。その後、前の質問が落ち始めてから次の質問が降り始めるまでの間を300msから500msに広げ、最後に、前の質問の要素がすべて落ちきってから（落ち始めてから1660ms後）次の質問が降り始めるようにした。見た目は `docs/visual-language.md` 4.5節、時間と値は `src/client/controller/question-transition.ts`。操作への応答とみなすため、`docs/visual-language.md` 1章の「一つの動きの所要時間は1.4秒以上」という原則は適用しない。入れ替えの間（3320msに余裕の100msを足した3420ms）は「戻る」「次へ」を無効にし、質問の区画を `inert` にする。また、前の質問は最後の要素が落ち終わるまで（1660ms）DOMに残り、質問の区画も3420msの間 `inert` になるため、E2Eテストの `expectQuestion` は入れ替えが終わるまで待つ。

- **破片の面の光の筋を消した（2026-11-26、ユーザーの指示）**。破片の面に白い光の筋を重ねていたが、点光源の細い線、太い帯、ぼかした光だまり、粗さ0の鏡に映る面光源の像と作り直しても意図に合わなかったため、機能ごと消した。破片はアウトラインと塗りだけで描く。`ShardPose.streak`、`streakOf`、光源と鏡の定数、描画の切り抜きとそのテストを削除した。ブルーム、アウトライン、破片の配置と動きは変えていない。
- **破片の不透明度を上げて明るくした（2026-11-26、ユーザーの指示）**。破片が透明で、背景の黒とハードライト合成で暗く見えていたので、破片ごとの不透明度を30〜75%から60〜95%へ上げた。乱数の列は変えていないので配置は同じ。1920×1080、`time=40,000` の輪で、破片のある画素の平均の明るさが108から137（0〜255）になった。明るさ150の破片はハードライト合成のため、不透明度を上げても約52/255までしか上がらない。さらに明るくするなら、破片の明るさの下限（150）を上げる。
- **質問の回答を受け付けて、輪が戻り始める瞬間に、中心から波紋を広げた（2026-11-26、ユーザーの指示）**。展示ディスプレイは回答の内容には反応しないまま、回答を受け付けたことだけを波紋で伝える。サーバーは回答を受け付けた時刻を `answeredAt` として状態に持ち（`src/shared/machine.ts` の `answer`。最終問の回答でも設定し、「戻る」では変えず、`idle` へ戻ると `null`）、展示ディスプレイへ配信する（`toDisplayState`。この項目を持たない保存済みの状態は `null` として読み、波紋を出さない）。ディスプレイは補正済みサーバー時刻と `answeredAt` の差（輪が縮み切って戻り始める0.45秒後を0とする。最初は回答の瞬間を0とした）だけから輪の位置と不透明度を求める（`src/shared/ripple.ts` の `rippleRings`、`computeScene` の `ripple`）ので、全画面で同じになる。細い白の輪2本が、二本目は0.3秒遅れて、4.8秒で画面の隅の外まで広がりながら細く薄くなって消える（最も濃いときの不透明度は0.34、0.22）。最初は3本を0.6秒ずつ遅らせたが、ユーザーの指示で2本、0.3秒の間隔にした。破片の上に重ねる専用のcanvasに描く（`Display.svelte`、`src/client/common/ripple.ts`）。reduced-motionでは出さない。一つ前の「回答に反応させない」の指示とは、回答の内容に反応しない点は変えずに、受け付けたことだけを伝える波紋を足す形で両立させた。見た目は `docs/visual-language.md` 3.2節。
- **質問の回答を受け付けた瞬間に、破片の輪を一瞬縮めて戻した（2026-11-26、ユーザーの指示）**。波紋と同じ `answeredAt` を起点に、輪の半径だけが0.2秒で15%縮み（`easeInOutSine`）、押された勢いで戻るように、縮み切った点を速度0で縮む動きから途切れずにつなぎ、戻る側は `easeInOutSine` の時間を前へ寄せて（`ANSWER_PULSE_RELEASE_BIAS` = 2.5）、速度0から勢いよく立ち上がって早めに最高速に達し、減速しながら1.75秒で元の大きさへ着く（元の大きさを超えない）。縮む側は0.45秒。合わせて2.2秒で、`docs/visual-language.md` 1章の「一つの動きの所要時間は1.4秒以上」を満たす。最初は縮む側を0.15秒の `easeOutCubic`、戻る側を `easeInOutSine` にしたが、動き出しが急だったので縮む側を `easeInOutSine` にし、戻る側は、「押された勢いで戻る感じ」という指示を、いったん減衰振動（元の大きさを超えて揺れ戻る）にしたが、「勢いがつくことと弾性があることは別」と指摘されて、行き過ぎない `easeOutCubic` にしたところ、縮み切った点で速度が0から最高速へ飛んで「ガク」となると指摘されたので、縮み切った点の速度をつなぐ形にした。さらに「全体をもう少し滑らかにゆっくり」と指示されて、縮む側を0.25秒から0.45秒、戻る側を1.15秒から1.75秒にし、前へ寄せる度合いを3から2.5へ下げた。破片の大きさ、枚数、色は変えない。`question` と、最終問の回答で入った `judging` だけで動き、reduced-motionでは動かない。計算は `src/shared/motion.ts` の `answerPulseScale`（`shardLayer` の `scale` にかける）。以前の「回答に反応させない」の指示は、回答の内容に反応しない点を変えずに、受け付けたことだけを波紋と収縮で伝える形で両立させた。

- **輪をゆっくり不規則に呼吸させた（2026-11-25、ユーザーの指示）**。輪全体の半径を基準の0.9〜1.1倍の範囲で変える。周期15秒、23秒、41秒の三つの正弦波を重み0.5、0.3、0.2で重ね、ふくらむ深さと間隔を毎回変える。一つの呼吸は12.46〜17.09秒で、三つを重ねた形は14,145秒（約3.9時間）で元に戻る。最初は0.95〜1.05倍、周期19秒、31秒、53秒（一つの呼吸は16〜22秒）にしたが、ユーザーの指示で振れ幅を2倍にし、呼吸を `docs/visual-language.md` 1章の「繰り返す動きの周期は12秒以上」という決まりを満たす範囲で最も速くした。補正済みサーバー時刻から求めるので全画面で同じ大きさになり、回答には反応しない。reduced-motionでは時刻を進めないので呼吸しない。計算は `src/shared/shards.ts` の `ringBreath`、見た目は `docs/visual-language.md` 3.2節と4.4節。

## 判断に迷った点

ユーザーの判断が必要な点。実装はそれぞれ下記の仮の判断で進めている。

1. **（2026-11-26に解消）`intro` 中に新しく接続した展示ディスプレイの待機巡回の基準時刻**。展示ディスプレイが写真を置かなくなり、巡回の基準時刻が要らなくなった。
2. **（2026-11-26に解消）結果開始後に接続した展示ディスプレイの写真**。展示ディスプレイが写真を置かなくなり、写真の読み込みを待つ処理をやめた。
3. **仮の `PUBLIC_ORIGIN` でもproduction buildが通る**。ビルド時に確かめられるのはHTTPS、末尾スラッシュなし、`dpc-school-festival.<subdomain>.workers.dev` の形までで、subdomainが実在するかはアカウント情報がないと確かめられない。仮値 `tbd-subdomain` のままデプロイしないこと。
4. **`sequence` の仮データ**。「はじめる」の後に再生する演出の内容は未定のため、仮の `opening`（3.6秒）を `intro` の前に置いた。再生中はiPadに操作手段を置かず、止めるには管理画面の強制リセットを使う。
5. **写真の長辺**。表示用は原本の寸法（長辺2048px）のまま書き出している。4Kディスプレイでは拡大表示になる。
6. **原本の管理**。`photos/originals/` はリポジトリへコミットしていない。原本をリポジトリで管理するか、別の場所に保管するかの決定が必要。
7. **会場サーバーに認証がない**。施設の閉じたネットワークの中だけで使う前提にした（ユーザーの判断）。来場者のスマートフォンが同じネットワークにつながると、`/admin` を開いて強制リセットなどができてしまう。施設のネットワークに来場者向けのWi-Fiが同居していないかを設営前に確かめる。
8. **写真の仮のタグ**。提供された12点の色タグ、内容のタグ、雰囲気のタグ、説明は、写真の主題から仮に付けた値（`src/data/photos.ts`、`tagStatus: "provisional"`）。`shareAllowed`、`creditName`、`idleOrder` も仮の値のまま。写真担当による確定が必要。写真が12点しかないため、一回の体験で選べる写真は10枚に届かないことが多く、不足枚数は記録に残る。
9. **写真の枚数と段階内の順位（仮）**。一回の体験で選ぶ写真は10枚（`PHOTO_POLICY.sessionPhotoCount`）、段階3の枠は設けていない。段階内の順位はhandoffで未決定のため、段階1と段階3はAIの判定順、段階2は全体の色タグで合う写真を先にした。
10. **二色の見せ方（仮）**。handoffは演出を定義していないため、展示ディスプレイは画面ごとに二色を交互に見せ（画面1が一色目、画面2が二色目）、iPadと結果ページは二色の混色プレビュー（13段のグラデーション）を見せる。結果の広がり方（`RESULT_FORMS`）は8種類を13色へ、色相の近い色が同じにならないよう割り当てた。管理画面の表示確認は色だけを見せる（写真はセッションごとに選ぶため）。
11. **AIの呼び出しの設定（仮）**。モデルは `mistral-small-latest`、一回の呼び出しは9秒で打ち切り、やり直しは一度、選定全体の上限は30秒（`src/data/ai.ts`）。実際のAPIでの応答時間は確かめていない。上限の30秒は来場者の待ち時間として長い可能性がある。
12. **結果の記録の保存期間**。回答を含む記録を会場サーバーのSQLite（`data/exhibit.sqlite`）に残し続ける。消す時期（公開終了日時の後など）と、その仕組みは未実装。結果ページのWorkerのKVに置いた公開部分は、公開終了日時に消える。
13. **写真の選定の指示の変更**。handoffの `prompts/photo-selection.txt` は色と内容の両方をAIに判定させるが、色の適合は写真の色タグから実装側で判定する方式（handoff 7.1節の「人のタグ」）にしたため、AIには内容の適合だけを判定させるよう指示を書き換えた。色の選定の指示は原文のまま。
14. **Q3とQ4の補助文、Q4の案内文**。handoffにないため仮に書いた（`src/data/questions.ts`）。
15. **電球の色と明るさ（仮）**。白色は約4000K（xy 0.3805, 0.3768）、明るさは最大（254）、白色から色へ3秒、色から白色へ2秒（`src/data/lights.ts`）。色はパレットの色（sRGB）から計算した色度座標を送る。仕様書11章のとおり、会場で色ごとに調整した値を `colors` に書けるようにしたが、まだ空。
16. **電球の並び順の決め方**。登録した順とし、並べ替えのコマンドは作っていない。順を変えるには登録を外して登録し直す。
17. **中継スクリプトが展示に接続できない間の電球**。最後の色のまま待ち、白色へは戻さない。結果の表示中に回線が切れたときに、色が途中で消えないようにするため。
18. **結果ページが開けるまでの遅れ**。QRコードは結果が決まった時点で表示するが、結果が結果ページのWorkerへ届き、Workers KVに反映されるまで（通常は数秒、最大60秒程度。施設回線が切れていれば回線が戻るまで）、結果ページのデータはHTTP 404になる。結果ページは「結果を準備しています」と表示して約3分間読み直すが、それを過ぎると「ページが見つかりません」という表示になる。そのときは少し待って「もう一度読み込む」を押すよう案内する。
