# カラー診断インタラクティブ展示 仕様書

## 1. 文書の位置づけ

本書は、文化祭で実施するカラー診断展示の企画・制作・当日運用における基準とする。
未確定事項は末尾の「要決定事項」に集約し、それ以外はMVPの暫定仕様として実装を進める。

## 2. 体験の目的

来場者が直感的な質問に答えると、その回答から一つの「今の自分を表す色」が決まり、写真・画面・教室内の光が同じ色へ変化する体験を提供する。

この診断は医療・心理・美容上の判定ではなく、展示作品として楽しむためのものとする。「似合う色」の断定ではなく、「回答から選ばれたあなたの色」と表現する。

### 体験完了の条件

- 来場者が説明を受けなくても、開始から結果表示まで一人で操作できる。
- 結果の色、色名、短いメッセージが同時に表示される。
- 結果表示に合わせて、すべての展示ディスプレイが同じ結果セッションへ切り替わる。
- 次の来場者が前の回答を見ずに、新しい診断を開始できる。

## 3. MVPの範囲

### 実施するもの

- iPad上での診断操作
- 選択回答に基づく結果色の決定
- 複数ディスプレイへの同期表示
- 結果色に対応する写真作品の表示
- 結果画面からのデジタル結果受け渡し
- スタッフによる強制リセットと再接続状態の確認

### MVPでは実施しないもの

- 氏名、年齢、連絡先などの個人情報収集
- カメラや顔画像を用いた自動診断
- 来場者自身による写真投稿
- AIによる診断文や画像のリアルタイム生成
- フルカラー印刷
- 複数人の同時診断

即時印刷と高度な照明制御は、機材と現地検証の結果を踏まえて追加する。

## 4. 利用者と端末

| 種別             | 役割                     | 操作                                               |
| ---------------- | ------------------------ | -------------------------------------------------- |
| 来場者           | 診断を受ける             | iPadで回答し、結果を受け取る                       |
| 展示ディスプレイ | 写真作品と演出を表示する | 操作なし。受信した状態を全画面表示する             |
| 運営スタッフ     | 当日の進行と復旧を行う   | 管理画面から開始可否、接続状態、リセットを操作する |

iPadの画面ミラーリングは使用しない。iPad、展示ディスプレイ、管理画面はそれぞれ専用のWeb画面を開き、同一の展示セッション状態を共有する。

## 5. 一回の体験フロー

目標所要時間は一人あたり2分以内、うち質問回答は60秒以内とする。

| 段階     | iPad                               | 展示ディスプレイ                         | 終了条件                         |
| -------- | ---------------------------------- | ---------------------------------------- | -------------------------------- |
| 待機     | タイトルと「診断をはじめる」を表示 | 全色の写真を静かに巡回表示               | 開始ボタンを押す                 |
| 導入     | 所要時間と診断の位置づけを表示     | 待機演出を継続                           | 「進む」を押す                   |
| 質問     | 一問ずつ選択肢を表示               | 回答に反応する抽象的な色・形の演出を表示 | 全問に回答する                   |
| 判定     | 短い判定演出を表示                 | 全画面を一度暗くし、結果演出に備える     | 1.5〜3秒の演出が終わる           |
| 結果発表 | 色名、色面、短いメッセージを表示   | 結果色と対応写真を一斉に表示             | 結果が全画面へ配信される         |
| 持ち帰り | QRコードと「最初に戻る」を表示     | 写真展示を継続                           | 手動終了または60秒経過           |
| リセット | 待機画面へ戻る                     | 3秒以内に待機演出へ戻る                  | 回答とセッション表示が破棄される |

質問中は、選択肢を押した直後に選択状態が視覚的に変化する。意図しない二重入力を防ぐため、選択確定後に次の質問へ進むまで同じ選択肢を再受付しない。前の質問へ戻った場合は既存回答を表示し、再選択を許可する。

## 6. 診断仕様

### 6.1 質問

- MVPは全7問とする。
- 各問は2〜4個の選択肢を持ち、未選択のまま次へ進めない。
- 質問文は一読で答えられる長さとし、性格の優劣を感じさせる表現を避ける。
- 正解・不正解や進捗を競わせる得点表示は行わない。
- 画面上部に現在位置を `3 / 7` の形式で表示する。

質問テーマは「今選びたいもの」に統一する。季節、時間帯、場所、光、音、手触り、過ごし方の7テーマを基本案とし、心理診断のような断定を避ける。

### 6.2 結果色

MVPは8結果とする。色名、表示用カラーコード、説明文、写真セットを一つの結果定義として管理する。

| ID      | 表示名（仮）       | 基準色（仮） | 写真の方向性           |
| ------- | ------------------ | ------------ | ---------------------- |
| red     | ルビーレッド       | `#C9364F`    | 熱、生命、近距離の質感 |
| orange  | コーラルオレンジ   | `#F0784B`    | 夕方、親密さ、温度     |
| yellow  | サンイエロー       | `#E5B83B`    | 光、開放感、軽さ       |
| green   | エメラルドグリーン | `#2F9B78`    | 植物、水、静かな成長   |
| cyan    | アクアブルー       | `#39A8B8`    | 透明感、風、反射       |
| blue    | コバルトブルー     | `#315AA9`    | 夜、奥行き、集中       |
| violet  | アメジスト         | `#7653A6`    | 影、余韻、非日常       |
| magenta | マゼンタピンク     | `#B94083`    | 華やかさ、遊び、躍動   |

基準色は画面間の演出同期に用いる代表値であり、展示写真を単純に着色するための値ではない。混色名も一つの結果色として扱い、二つの診断結果を同時に返す仕様にはしない。

### 6.3 判定方法

- 各選択肢は、8色のうち1〜2色に加点する固定スコアを持つ。
- 全回答の合計点が最も高い色を結果とする。
- 同点時は、後半3問で得点が高い色を優先する。
- それでも同点の場合は、色定義に設定した固定優先順位で決定する。
- 同じ回答列からは常に同じ結果を返し、ランダム判定は行わない。

質問・選択肢・配点はコードへ直接埋め込まず、一つの診断定義データとして管理する。公開前に全回答パターンを集計し、特定の色が一度も出ないこと、および一色へ極端に偏ることがないか確認する。

## 7. 画面仕様

### 7.1 iPad操作画面

- 縦向きを基本とし、横向きでも操作不能にならないレイアウトにする。
- 一画面に一つの主操作だけを置く。
- 選択肢全体をタップ領域とし、押下、選択済み、無効の状態を見分けられるようにする。
- 色だけで状態を区別せず、形、枠、ラベルの変化を併用する。
- 結果画面には色名、色面、50文字以内のメッセージ、QRコード、終了操作を表示する。
- ブラウザの更新や一時的な通信切断後は、進行中セッションへ復帰する。結果確定後の再読み込みでも同じ結果を表示する。

### 7.2 展示ディスプレイ

- 写真を作品として見せるため、原則として一画面につき一作品を表示する。
- 写真はトリミングせず全体を表示し、余白を確保する。背景色は結果色との調和を優先する。
- 複数画面に同一写真を複製せず、一つの結果に紐づく写真セットから画面ごとに異なる作品を割り当てる。
- 画面数より写真数が少ない場合に限り、一部画面で色面または色名のタイポグラフィを表示する。
- 結果発表の開始時刻は全画面で共有する。通常運用時の切り替え差は目視で違和感のない範囲（目標200ms以内）とする。
- 新規接続または再接続した画面は、現在の展示状態を受信して途中参加する。
- 写真の読み込み完了前に結果へ切り替えず、必要素材は待機中に先読みする。

各ディスプレイには固定の画面IDを割り当てる。写真の割り当て順は画面IDで決め、再読み込みによって入れ替わらないようにする。

### 7.3 管理画面

管理画面は来場者から見えない端末で使用し、次を提供する。

- iPadと各展示ディスプレイの接続状態、最終受信時刻の一覧
- 現在の段階と結果色
- 全端末を待機状態へ戻す強制リセット
- 診断受付の一時停止と再開
- 各結果色の表示確認
- 照明連携を追加した場合の手動オン・オフ

## 8. 同期と状態管理

一回の診断をセッションとして管理し、最低限次の状態を共有する。

```text
sessionId
phase: idle | intro | question | judging | result
questionIndex
answers
resultColorId
phaseStartedAt
revision
```

- 状態の正本は一か所に置き、各画面は受信状態を表示する。
- 更新ごとに単調増加する `revision` を付け、遅れて届いた古い状態で画面を巻き戻さない。
- 結果発表は配信受信時ではなく `phaseStartedAt` を基準に開始し、画面間の差を抑える。
- 接続が切れた展示画面は最後の表示を維持し、接続中を示す警告を来場者向け画面には出さない。管理画面には切断を表示する。
- iPadから結果確定要求を再送しても、同じセッションに別の結果を生成しない。

当日の校内回線に依存しすぎないよう、展示端末間の同期は会場内の専用ネットワークで完結できる構成を優先する。

## 9. 結果の受け渡し

MVPはデジタル受け渡しとする。結果画面にセッション固有のQRコードを表示し、読み取るとその色の結果ページを来場者自身の端末で開く。

結果ページには次だけを含める。

- 色名と色面
- 診断メッセージ
- 展示写真のうち配布許可済みの代表画像
- 展示名と開催情報

共通QRコードだけでは個別結果を識別できないため採用しない。運用上どうしても共通QRが必要な場合は、結果画面に短い受取コードも表示し、遷移先で入力する方式へ変更する。

結果URLは推測しにくいランダムIDを持ち、氏名や回答内容を含めない。保存期間は文化祭終了後30日を暫定上限とし、期限後は結果データを削除する。外部公開環境を用意できない場合は、QR受け渡しを無効化して画面表示のみで運用する。

## 10. 照明・装飾連携

照明連携はWeb画面と切り離した出力先として扱い、結果色IDを受けて事前登録した照明シーンを再生する。

- RGB値をそのまま照明へ送らず、会場で調整した8個の照明シーンを用いる。
- 結果発表の開始時刻に合わせ、0.5〜1.5秒で現在色から結果色へ遷移する。
- 通信失敗時も画面上の診断を完了させ、管理画面だけに失敗を表示する。
- 強制リセット時は待機用の白色または中立色へ戻す。
- 明滅演出を使用する場合は強い高速点滅を避け、事前に安全性を確認する。

採用機材と制御方式が決まるまでは、照明連携を必須の完了条件に含めない。

## 11. 写真素材の要件

- 各結果色につき、`展示ディスプレイ数 + 2` 点以上を目安に用意する。
- 色だけで分類せず、結果メッセージと写真のテーマが一致するものを選ぶ。
- 原本、展示用データ、スマートフォン配布可否、作者クレジットを管理する。
- 展示用データは実ディスプレイの解像度と色味で確認し、文字やUIを焼き込まない。
- 縦横比が異なる写真は余白で吸収し、作品の主要部を自動クロップしない。

## 12. 非機能要件

### 応答と安定性

- iPadのタップから選択表示の変化までは100ms以内を目標とする。
- 結果確定から全ディスプレイの演出開始までは3秒以内とする。
- 連続100セッションの実行で、再読み込みを必要とする停止が起きないことを確認する。
- 通信切断後30秒以内に回線が戻った場合、手動操作なしで再接続する。

### アクセシビリティ

- 本文と操作文字は、想定閲覧距離で読めるサイズにする。
- 操作UIは色覚だけに依存せず、十分な明度差を持たせる。
- 動きが苦手な来場者向けに、iPad側では大きな動きを抑えた表示を使用する。
- 音声は体験成立の必須要素にしない。追加する場合は消音でも情報が欠けないようにする。

### プライバシー

- 個人を特定できる情報を入力させない。
- 回答内容を保存する場合は、展示改善用の匿名集計に限定する。
- 管理画面以外から他人の回答履歴を閲覧できないようにする。

## 13. 当日運用

### 開場前

1. 全端末を同一ネットワークへ接続する。
2. 管理画面でiPadと全ディスプレイが接続済みであることを確認する。
3. 8色の表示確認を行い、画面と照明の対応を確認する。
4. QR結果ページを会場の外部回線から開けることを確認する。
5. 一回の通し診断を行い、リセット後に全画面が待機へ戻れば開場可能とする。

### 障害時

- 一画面だけ切断した場合は、該当ブラウザを再読み込みして接続状態を確認する。
- 全画面が同期しない場合は、受付を一時停止し、管理画面から強制リセットする。
- QR配布だけが失敗した場合は、画面展示を継続し、QRを非表示にする。
- 照明だけが失敗した場合は、照明連携を無効化して画面展示を継続する。

## 14. 受け入れ条件

- 7問すべての回答経路で、定義済み8色のいずれか一つが返る。
- 戻る操作で回答を変更すると、変更後の回答だけが判定へ反映される。
- 結果確定操作を連打または再送しても、一セッションにつき結果は一つだけ生成される。
- 3台以上の展示ディスプレイが、同じ結果を目標200ms以内の差で表示開始する。
- 展示ディスプレイを結果表示中に再読み込みすると、同じ結果表示へ復帰する。
- 強制リセット後、回答、結果、QRコードが次の来場者へ残らない。
- 一台が切断しても、ほかの端末と診断操作は停止しない。
- 外部回線がない構成でも、QR以外の診断と展示が完了する。
- 実機iPadで主要操作が画面外へはみ出さず、縦向きでスクロールせず回答できる。

## 15. 要決定事項

以下は実装または素材制作へ入る前に担当者が決定する。

| 優先度 | 決定事項                                 | 決定に必要な情報                 | 期限の目安     |
| ------ | ---------------------------------------- | -------------------------------- | -------------- |
| 高     | 設置するディスプレイの台数、解像度、向き | 教室の間取りと利用可能機材       | 画面設計前     |
| 高     | 7問の本文、選択肢、配点                  | 企画担当と写真担当のレビュー     | 診断実装前     |
| 高     | 8色の正式名称、カラーコード、メッセージ  | 写真作品と実機の色確認           | 素材組み込み前 |
| 高     | 結果ページを外部公開できるか             | 学校の公開規定、サーバー、回線   | QR実装前       |
| 中     | 写真点数、縦横比、配布許可               | 写真担当の素材一覧               | 展示画面実装前 |
| 中     | 照明機材と制御方法                       | 会場機材、電源、ネットワーク     | 照明連携着手前 |
| 低     | 印刷を追加するか                         | 予算、消耗品、印刷速度、保守担当 | MVP完成後      |

## 16. 将来拡張

MVPの当日運用が安定した後に限り、次を個別に検討する。

- レシートプリンターによる色名と短文の即時発行
- 事前印刷カードの在庫管理と配布
- 来場者数と結果色分布の匿名集計
- 結果色に応じた音響演出
- 複数診断ブースの同時運用

リアルタイムフルカラー印刷は、印刷待ちが体験時間と導線へ与える影響が大きいため、MVPとは別企画として評価する。
